## 2. Sign

Prerequisites: the release secret key is in the local GnuPG keyring, `gh` is
authenticated with push rights to `MindLink-ApS/BitSov-bitsov`, and `<main sha>`
is the post-merge release commit recorded above, on `origin/main`, containing
#266 and this rc11 docs/version PR. Use the full SHA, not a pre-merge tip.

```sh
scripts/release-sign.sh v0.3.0-rc11 <main sha>
```

The script:

1. Creates and pushes a signed `v0.3.0-rc11` tag on `<main sha>`. If the tag
   already exists on that commit with a valid signature, it reuses it.
2. Waits for the tag's `ci.yml` push run. It requires that run to have built
   exactly `<main sha>`, and stops if CI fails.
3. Downloads the five draft binaries (`bitsov-darwin-aarch64`,
   `bitsov-darwin-x86_64`, `bitsov-linux-aarch64`, `bitsov-linux-x86_64`,
   `bitsov-windows-x86_64`) and checks each against its `.sha256`.
4. Writes `SHA256SUMS`, signs it as `SHA256SUMS.asc`, verifies the signature
   and attaches both files to the **draft**. It never publishes.

## 3. Verify independently before publishing

Use a fresh directory and a throwaway keyring, so the result does not depend
on the signing machine's keyring:

```sh
work=$(mktemp -d) && cd "$work"
gh release download v0.3.0-rc11 --repo MindLink-ApS/BitSov-bitsov \
  --pattern 'SHA256SUMS*' --pattern 'bitsov-*'
export GNUPGHOME=$(mktemp -d)
curl -fsSL https://raw.githubusercontent.com/MindLink-ApS/BitSov-bitsov/main/RELEASE_KEY.asc | gpg --import
gpg --fingerprint B299274C200301714DC6F51A7C2D6F8AC842EF6E
gpg --status-fd 1 --verify SHA256SUMS.asc SHA256SUMS
shasum -a 256 -c SHA256SUMS
git -C <bitsov checkout> fetch origin --tags && git -C <bitsov checkout> verify-tag v0.3.0-rc11
```

`RELEASE_KEY.asc` from a local checkout of `main` instead.
