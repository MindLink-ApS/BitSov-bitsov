# BitSov v0.3.0-rc9 — release notes (paste into GitHub)

**Pre-release.** Not for production use. These notes describe the node; they do
not establish app support, hardware-key attestation or mainnet qualification.

**Status:** prepared on `chore/release-v0.3.0-rc9`, 2026-10-06. No tag, push,
upload or publication is part of this preparation. A release still requires
operator review, a protected signed tag and verified signed artifacts under
[release policy](../ops/RELEASE_POLICY.md).

## Why upgrade

rc9 adds launcher password handoff, opt-in local owner device authority and an
encrypted two-phase first-run ceremony. Hubs can opt into bounded LSPS2 funding;
Porch readers check availability and the recipient's price before paying.
Storage pagination, pairing, chain synchronization, on-chain reservations,
logging and shutdown include operational fixes from the pilot.

Read [UPGRADING](../UPGRADING.md) before replacing a retained node. rc7 needs
explicit `NODE_INITIALIZED` repair and migrations **020–028**; rc8 already has
those markers/migrations in a healthy installation. A retained
`[pricing] web_content_msat` below **1000** must be raised or removed, including
rc7's generated value of 50. Do not reinitialize, copy seeds or restore stale
Lightning state. After the first LDK start on rc9, preserve current state and
roll forward only.

## What's in rc9

This covers **all 31 merged commits** in `git log v0.3.0-rc8..HEAD` at the source
commit below. Issue references are distinguished from merged PRs where useful.

### Local owner, password input and bootstrap

- **Password descriptors (#232):** `init/start --password-fd <n>` consumes one
  bounded UTF-8 password to EOF (`0` is stdin; other inherited descriptors on
  Unix). Maximum 4096 bytes, trailing CR/LF removed, mutually exclusive password
  sources, no prompt/plaintext fallback on malformed input. Init implies
  encryption. Owned buffers are zeroized; the launcher must close the pipe and
  protect/erase its own copy. Descriptor input alone leaves device approvals
  off with `seed_password_not_typed`. No Keychain integration is in the node.
- **Local owner device authority (#235):** explicitly launch with
  `--password-fd <n> --local-owner-device` on every run. Requires an encrypted
  seed with no plaintext sibling; derives the owner verifying key at startup,
  then drops the password and signing key. Existing owner-approved devices can
  authorize recipient-bound spend envelopes. It opens no `control.sock`,
  enables no console grants, and adds no remote approval authority. Older
  device records default to `enrolled_by: "console"`; owner signatures remain
  mandatory. First-run enrollment is the separate flow below.
- **Encrypted two-phase bootstrap (#237):** on a positively empty loopback
  install, create-pending returns a phrase once, held only in zeroizing memory.
  Finalize verifies three backup words and, with local owner enrollment enabled,
  P-256 possession before signing the first device's owner approval. Seed,
  pairing/device state and config are committed before `NODE_INITIALIZED`.
  Success exits; the launcher explicitly restarts with the same password and
  flag. Cancellation, expiry and interrupted commits fail closed. No live-node
  seed replacement, phrase re-download or device delegation is added.
- **Legacy create/restore behavior changed too (#237):** HTTP bootstrap
  create/restore now write **`identity/mnemonic.enc` whenever any startup
  password is present**, including `--password`/`--password-file` without local
  owner mode. No-password bootstrap retains plaintext behavior. Supplying a
  password does not enroll a device or automatically convert an existing seed.
- **Refused state (#238):** after a failed local-owner commit,
  `GET /api/v1/bootstrap/state` reports `state: "refused"` with create/restore
  disabled before restart too. It exposes no reason, disk details or repair
  instructions; CLI restart diagnostics retain those. Marker repair does not
  fix a pre-alignment mnemonic path, stale pairing fingerprint or missing
  device enrollment; recover those explicitly as described in the guide.

See [password input](../operations/password-input.md),
[device keys](../security/device-keys.md) and
[two-phase bootstrap](../security/pairing.md#two-phase-local-bootstrap).
The node cannot attest Secure Enclave storage. Mac launcher release requires
Developer ID signing and hardened runtime; an unsigned launcher must say
**local owner (unsigned app)**. A writer of the pairing grant file can still
forge grant provenance/budget fields: signed device enrollment is not a signed
grant ledger. Hosted seed custody remains hosted custody.

### Lightning, LSPS2 and on-chain funding

- **Hub provider (#233):** optional LDK LSPS2 service with a private pilot token,
  opening-fee skim, channel overprovisioning and a nonzero forwarding tariff.
  Off by default; mutually exclusive with LSPS2 client mode on the same node.
  Service advertising remains off. Service mode enables private forwarding even
  when the ordinary private-forwarding option is false. Funding buys liquidity,
  never admission: later communication needs its own settled payment.
- **Caps, retries and metrics (#236):** owner-selected funding priority and
  whole-transaction fee cap, durable concurrency/capital reservations and at
  most five open attempts within 60 seconds. Retries preserve the original
  policy; ambiguous dispatch retains its slot and capital for reconciliation.
  Tariff installation retries with backoff and scans unpriced matching channels
  on restart; it does not reprice existing nonzero tariffs. Hub Prometheus
  counters report opens, fees, capital, pending/failed opens and retries.
- **Manual private forwarding (#226, issue #225):** ordinary LDK nodes opt in
  with `forward_to_private_channels = true`; default false. This is separate
  from LSPS2 service mode's private forwarding requirement.
- **Owner funding fees (#224, issue #190):** open-channel supports
  `economy`/`normal`/`fast` (144/12/6-block estimator targets), read-only preview
  under owner spend authority, and an optional complete funding transaction
  fee cap checked before signing. Missing/stale estimates refuse. Preview is
  not a reservation; confirmation times are estimates. No automatic repricing
  or wider-cap retry, and arbitrary LDK fee rates remain unsupported.
- **Serialized on-chain operations (#191, issue #189):** opens, sends, closes
  and bumps share a cancellation-safe operation gate. Local spend ownership
  survives restart, mempool eviction and shallow reorgs; reconciliation is
  bounded. Slow funding visibility returns `pending_visibility` with channel
  ID/txid, not permission to repeat. Owner release requires a definitive
  configured-source absence check; it has no force option. Closing balances
  exclude unfunded removed channels only on proven absence (#192); inconclusive
  evidence must not invent either lost funds or spendable balance.

**Pilot limits:** durability begins when BitSov's vendor handler journals an
LSPS2 request. Upstream **lightning-liquidity 0.2.0 retains a pre-delivery
event/peer-state persistence crash window**, with no event acknowledgment API.
This release does not repair it; reconcile pending top-ups before reissuing.
The journal has a 4096-request tombstone limit. Unattributed closed monitors
can conservatively reserve the entire capital budget. Opening-fee metrics are
at-least-once observations capped per request, **not an accounting ledger**;
tariff retry totals reset on restart. The hub remains a graph observer and
availability dependency. No automatic failover, reserve waiver or production
provider qualification is claimed.

See [LSPS2 pilot and configuration](../LSPS2-LIQUIDITY.md),
[funding fees](../ops/funding-fees.md) and
[on-chain reservations](../v2/SERIALIZED-ONCHAIN.md).

### Porch quote before paying (#234)

`porch_quote_v1` checks availability and current recipient price before any
single-peer kind-500 payment, including Browse. Metadata quotes return no page
content and require a currently privileged connection. Upgrade reader and
server; older servers fail closed before payment. Missing, empty, oversized or
unsafe pages refuse without buying the page. A metadata check is not a content
reservation or UTF-8 validation: the file can still change before paid delivery.
Room compose rejects kinds 500/501/510 with `porch_room` before payment.

The default web-content price is **1000 msat (1 sat)**. Existing valid operator
prices remain; below-floor retained config fails validation, even if serving
is disabled. `web.page_price_msat` is legacy, not a separate charge override.

**Superseding older quotes is deferred.** Raising a tariff does not revoke
persisted lower delivery offers. A custom client can pay against an older
five-minute Porch offer, or an ordinary kind-500 offer lasting up to one hour.
Timely settled payments can arrive up to one further hour after settlement.
Restart does not revoke offers. Safe supersession needs durable tariff epochs
and offer/payment bindings that v1 does not store; deleting old offers would
also reject already-paid reads. Allow these windows to drain before relying on
a raised tariff as a hard minimum. The current admission and one-sat floors
still apply. See [Browse](../protocol/BROWSE.md#quote-before-payment-porch_quote_v1)
and [Porch implementation notes](../../NOTES-PORCH.md).

### Pairing, remote access and storage

- **Remote preparation (#192):** pairings may request spend elevation and read
  first-contact quotes; no remote grant/approval handler is opened. Status is
  client-bound and pending elevation is bounded per client.
- **Headless owner consent (#194, #197):** owner-only approval files cover spend,
  front-door and device enrollment, with cleanup/reissue across lifecycle
  events. Unavailable owner delivery returns `409 owner_approval_unavailable`.
  Codes do not travel through app HTTP or logs. Files are not a boundary against
  an app running under the owner's OS account.
- **Approval status (#211, issue #205):** a paired client may poll its own
  recipient-bound first-contact grant (`pending/approved/consumed/expired`).
  Polling grants nothing; compose consumes once. Approval is memory-only and
  fails closed across restart; app polling support is separate work.
- **Remote throttling (#214, issue #208; #220, issue #193):** pre-Noise handshake
  debt decays and may return a length-prefixed `rate_limited` JSON hint with
  `retry_after_secs` from 1–60. It is unauthenticated and can be absent; clients
  still need bounded backoff. Post-Noise HTTP quotas bind to authenticated
  pairing identity, survive reconnects and ignore forwarded-header claims.
- **Unreadable storage (#187, #221; issues #186, #188):** skip unreadable list
  rows without changing response shapes or rewriting data. Bounded refills and
  continuation cursors preserve progress through corrupt/all-unreadable pages.
  Optional diagnostic headers and owner status report loss; single-item reads
  and complete whitelist backups stay strict. Clients must honor continuation
  headers even on empty result pages.

See [pairing](../security/pairing.md), [remote access](../protocol/REMOTE-ACCESS.md)
and [storage list diagnostics](../v2/STORAGE-LIST-DIAGNOSTICS.md).

### Chain synchronization, operations and test coverage

- **Retry/ownership (#196):** independent bounded background wallet/fee retries
  and cancellation-safe Esplora sync ownership, with sanitized diagnostics.
- **Rate limits/broadcasts (#200):** shared Esplora cooldown honors bounded
  `Retry-After`; duplicate rebroadcasts back off and interrupted packages remain
  recoverable. Ghost funding suppression requires explicit absence, not a
  missing source, timeout or unknown status.
- **Readiness (#198, #202, #210, #218; issues #199, #204):** refuse unready
  admission quotes before invoice creation (`peer_not_ready`), sanitize
  privileged invoice refusals, share successful readiness height observations,
  fall back on unavailable heights and reject zero-height prices. A separate
  30-second Esplora tip cache reduces requests without claiming synchronization.
- **Authenticated Esplora (#215, #217; issues #209, #216):** opt-in owner-only
  credentials file for OAuth client credentials, in-memory token refresh,
  bounded deadlines/backoff, preserved upstream status and ordered fallback.
  Credentials never go to fallback hosts. No paid provider is selected by
  default; paying a server does not turn it into local validation.
- **Low-traffic profile (#223):** optional LDK Esplora intervals from 10–3600
  seconds; defaults remain on-chain 80 s / Lightning wallet 30 s / fees 600 s.
  The documented 600/60/1800 profile reduces polling but can delay on-chain
  observations. Core/Electrum and separate chain polling are unaffected.
- **Shutdown (#212, issue #206):** initialized-node construction (including
  chain backoff) and live operation share SIGTERM/SIGINT handling. Shutdown
  bounds Lightning to 15 seconds, cleanup to 10 and the process to 30. This
  bound does not cover first-run bootstrap or password acquisition. The service
  example uses `TimeoutStopSec=45`.
- **Logging (#213, issue #207):** node and LDK file logs each default to 10 MiB
  with five total files. Remove append/`tee` wrappers around `node.log` so
  external descriptors cannot defeat rotation. Journald retention and the
  security audit log are separate; rotation is not secret redaction.
- **Regtest harness (#201, #203):** three-node paid end-to-end scenarios,
  idle-link keepalive and corrected ghost-retry expectations. The suite now
  includes private forwarding and hub JIT scenarios from #226/#233/#236.
  Those scenarios require local Core/electrs and are not established by an
  ordinary workspace test run or the mock upgrade check below.

See [chain sources](../CHAIN-SOURCE.md), [logging](../operations/logging.md) and
[three-node paid tests](../three-node-paid-e2e.md).

## Defaults, migration and compatibility

Local owner device authority, owner console, hub LSPS2, LSPS2 client funding,
ordinary private forwarding, remote Noise access, paid peer exchange, node STUN
and paid/authenticated Esplora are all explicit opt-ins. Encrypted two-phase
bootstrap requires startup password input; first-owner enrollment additionally
requires the local owner flag. These opt-ins neither choose a public provider automatically nor grant
communication rights. App support must be checked separately.

Workspace version is **0.3.0-rc9** in all 13 packages; MSRV remains **1.88**.
No numbered SQL migration landed since rc8: SQLite embeds **001–028** and rc7
upgrades apply **020–028**. PostgreSQL keeps the corresponding embedded runner.
New local-spend/LSPS2 journals and device metadata still change persisted state;
there are no down migrations or general downgrade guarantee. Keep identity,
wallet/channel, pairing, quote, replay, payment and generation state together.

Existing rc8 limits remain: calls are a regtest signalling prototype with no
TURN; Browse is card/text only; Core/Electrum selection is not runtime failover;
Windows disk probing is not qualified; `money_signer`/`remote_signer` remain
design-only. The sqlx 0.8.0 dependency island and its future-compatibility warning
remain. Nothing in this preparation establishes platform signing/notarization.

## Human release checklist

This preparation ends at a local commit. Before a later release:

1. Review this source range, the upgrade prerequisites and app compatibility.
   Qualify retained/funded state separately from the scratch check. Resolve or
   explicitly accept the verification limitations below before release sign-off.
2. After review/merge, record the actual release source SHA and follow
   [release policy](../ops/RELEASE_POLICY.md) for the protected **signed**
   `v0.3.0-rc9` tag. No tag is created by these instructions being present.
3. Verify draft CLI assets, per-file checksums, SBOMs and required provenance;
   assemble and sign `SHA256SUMS` with the release key, then verify
   `SHA256SUMS.asc` and the selected artifact before use. Draft CI assets alone
   are not publication approval.
4. Only the authorized operator publishes the GitHub pre-release after sign-off.
