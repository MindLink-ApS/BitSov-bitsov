# BitSov v0.3.0-rc8 — release notes (paste into GitHub)

**Pre-release.** Not for production use. Describes what is built; nothing here is a supported platform claim.

**Status:** notes prepared on branch `release/v0.3.0-rc8-refresh`. Do **not** treat this file as a published release until the **signed** tag exists (`git tag -s` with the release key), CI has staged draft assets, `SHA256SUMS.asc` is attached, and an operator publishes the pre-release.

## Why upgrade from rc7

rc7 fixed startup probe / TLS issues. The node line now includes scoped pairing, budget grants, explicit non-dispatch refusals, exactly-once compose, BOOT-2 readiness, front door and paid Browse, Rooms bindings, Noise remote access, paid peer exchange, paid call signalling, device/owner-approval keys, seed encryption, and explicit Bitcoin Core/Electrum chain sources. rc8 prepares that line for an app update from `v0.3.0-rc7`; app support must be checked separately. No tag is created by this preparation.

Retained nodes: read [`docs/UPGRADING.md`](../UPGRADING.md) **before** replacing the binary (`NODE_INITIALIZED` repair; stale `KONSENSUS_SQLITE_MIGRATIONS_DIR`; migrations **020–028**; VM upgrade rules; seed / custody labeling; `[pricing] call_msat`; optional `[calls] stun_listen`; disk reserve/state generation; chain source and app API compatibility; MSRV **1.88**).

## What's in rc8

### Merged since the previous draft (`5cf12a5` → `62238c2`)

- **Noise-only remote access (#156):** optional public TCP tunnel to the scoped
  HTTP/WebSocket API, authenticated by pinned Noise transport keys and durable
  pairing bindings. Local token minting is excluded. Off by default; no new
  plaintext public HTTP listener. See [remote access](../protocol/REMOTE-ACCESS.md).
- **Browse (#149, #167, #173):** paid porch card/text reads over kinds 500/501/510,
  `porch_read_v1`, `/api/v1/browse/fetch` and memory-only `/browse/cards` cache.
  Requires an existing E2EE session/Knock; no implicit first-contact purchase.
  Serves the published card and flat `.md`/`.txt` pages, at most 256 KiB per reply.
  The enforced **1-sat minimum** also appears in advertised card/manifest prices
  and price tables despite lower config values or discounts. Bound replies
  never promote admission. Binary media, card relay and an app Browse screen
  are not established by this node change.
- **Rooms (#155):** `room_binding_v1`, fixed 2–4-node roster in ordinary encrypted
  kind-0 chats, with per-member outcomes and capability checks. No new wire kind,
  persistent room table, creator authority or membership mutation. Whole-room
  fan-out is untracked: only proven-unpaid refused members may be retried, as
  capped journaled 1:1 legs; never repay settled or unresolved members.
- **Paid peer exchange (#170):** off by default, owner-curated peer and label
  allowlists; signed short-lived quotes bind an encrypted snapshot to one
  settled kind-903 redemption. Unpaid requests and the legacy HTTP discover
  workflow refuse. This is the receiving wire service, not an automatic buyer.
- **Disk guard / rollback (#169):** 2 GiB default reserve, owner diagnostics and
  pre-dispatch `disk_low` refusals; embedded LDK also guards inbound HTLC claims
  and channel acceptance. Recovery/reconciliation remain available. Durable
  state-generation marker and lease precede SQL/LDK startup. This cannot prove
  backup freshness or make a stale Lightning-state restore safe.
- **Bitcoin Core (#175):** explicit file-authenticated pruned/full Core backend
  for chain reads and embedded LDK, with no public Esplora fallback. Retain enough
  block history for wallet catch-up; arbitrary historical txid lookup is not
  guaranteed on pruned nodes. Core cookie rotation requires BitSov restart.
- **Electrum (#180, #182):** explicit `server_url`, shared by chain reads and LDK,
  no default/discovery/fallback. Public endpoints require TLS; plaintext is
  restricted to loopback/private IPs (or `localhost`). `.onion` servers are
  rejected until a proxy transport exists; TLS IPv6 literals are also rejected.
  `operator` defaults to `third_party`. See [chain source](../CHAIN-SOURCE.md).
- **Honest status (#179):** `own_node` replaces the interim `trustless` label;
  nullable `chain_sync` reports observed LDK sync stalls without asserting
  readiness or exposing remote error text. No-fallback regression coverage
  guards configured chain-source behavior.
- **Balance breakdown (#178):** read-scoped wallet categories in sats alongside
  the unchanged legacy msat aggregate; unknown categories are omitted, and
  closing/contested amounts are not immediately spendable balances.
- **Actual fees (#184):** optional `fee_paid_msat` reports settled outgoing LDK
  routing fees on payment and compose results, including recovery where evidence
  survives. Authorization ceilings remain separate; no invented zero or fee.
- **Identity (#164, #174):** BIP-39 passphrase-aware mnemonic verification;
  zeroizing mnemonic request/seed/key material and vendored X25519 support.
  This reduces secret retention, not a guarantee that every process-memory copy
  can be erased or that hosted custody becomes local custody.
- **Ops tests (#177):** owner-token probes use isolated fixtures rather than live
  services. **Design documentation (#159):** adds `DESIGN-REASONING.md`; proposals
  recorded there are not implementation claims.

### Identity / pairing / custody
- **Touch ID device keys + owner-approval key + seed encrypt** (#153): pairing can bind a device key; owner approvals use a dedicated owner-approval key; optional encrypted seed on disk.
- **`--password-file`** (#153): opt-in non-interactive password for encrypted seed at `konsensus start`. File must be a regular file, owner-only (`0600`), no symlink. Starting this way leaves Touch ID approvals off (`seed_password_not_typed`) because the password was not typed. Suitable for systemd when the seed is encrypted; a VM seed remains custody either way.
- **`custody_mode` on owner `/status`** + **`docs/protocol/REMOTE-SIGNER.md`** (#154): reports `local_seed` | `encrypted_seed` | `hosted_custody` (`money_signer` and `remote_signer` are reserved — no config produces them yet). `[identity] hosted = true` or cloud tier wins over an encrypted seed and labels **hosted custody**. An encrypted seed on a hosted VM is not a third custody model: the node still decrypts into operator memory. Remote-signer design is documented; it is **not** implemented in this cut.

### Network / ops fixes
- **Address discovery** (#148): optional owner-set `[network] stun_server` learns a dialable public endpoint when `advertised_addr` is unset; explicit `advertised_addr` always wins. No default third-party STUN.
- **Prepared-op release** (#144): compose operations that fail before any payment move to `released` (nothing-paid) instead of staying stuck `prepared`; restart/reconcile heals proven-unpaid stuck rows.
- **Relative config → absolute `data_dir`** (#143): `konsensus start --config konsensus.toml` (bare relative path) no longer yields an empty data dir / admission-journal os error 2.

### Payments safety
- Proven non-dispatch is preserved end-to-end as HTTP `400` with `code: "not_dispatched"` (#115, #117), including capped re-admission refusals with a stable reason (#121).
- **Quoted capped re-admission** is generation-bound: the payer's quote and the recipient's generation must match (#127).
- Admission **fee ceilings are reported only at wallet dispatch** (#128).
- Invoice timestamp checks **tolerate small recipient clock skew** (#126).
- All-in Lightning caps cover principal and routing fees (#99); paid-send caps are node-enforced (#80). Existing LNbits configurations now fail closed (`not_supported`) because the integration cannot enforce per-payment routing-fee ceilings; see the upgrade guide before choosing LDK/LND.
- Incomplete paid recovery fails closed to `payment_unknown` (#119); paid resends back off while the peer is offline (#118); outbox recovery scans are bounded with replay tombstones (#116).
- Paid envelopes stay until atomic acceptance ACK (#103).
- Lightning **circuit breaker** timing and concurrent admission stabilized (#112): no queued call after the circuit opens; an older success cannot close a new circuit; older failures cannot extend cooldown; cooldown expiry admits a single recovery probe.

### Calls (regtest prototype)
- Paid **1:1 call signalling**, kinds **400–403** (#131). Call state and admission holds persist across restarts (migrations **027**, **028**). See [`docs/v2/CALLS-PROTOTYPE.md`](../v2/CALLS-PROTOTYPE.md).
- Configure `[pricing] call_msat` (default **10 000** msat; must be **> 0**) for the offer (kind 400). Answers, ICE, and hangup use `realtime_signal_msat`.
- Optional **own STUN responder** (#136): `[calls] stun_listen = "0.0.0.0:3478"` (UDP; **omit to keep off**). Binding-only (XOR-MAPPED-ADDRESS); no TURN/relay/auth. **Firewall:** allow inbound UDP on that port when enabled. Owner `/status` exposes `stun_port` / `stun_url`; `/health` does not.
- **App STUN is still owner-confirmed:** Settings → Calls sets `stun:host[:port]` (may use the node's `stun_url`). Nothing auto-enables. Without a saved STUN URL, calls use host candidates only.
- Also on `main` in this cut: mesh meetings prototype + `call_meeting_v1` advert (#138, #141); STUN/call cap follow-ups (#137).

### Web services (paid porch)
- `KIND_WEB_MANIFEST` / `KIND_PAGE_RESPONSE` **replies bind to the requester's paid proof** — no self-minted Lightning proofs (#129).
- Outstanding paid 500/510 requests are recorded in a **durable table** (migration **026**) and expired rows are swept (#132).
- Unbound zero-amount 501/510 still hit the Mock price floor; replies are never routed as requests.

### Front door
- **FrontDoorCard v1**: signed doorstep card (≤16 KiB, seq, 7-day expiry), owner publish / Read GET+verify+open, `front_door_v1` capability (#130). Knock stays existing first contact; doorstep is free to carry.
- Seq floor + identity check + fail-closed verify without a Bitcoin network (#133); adopted seq floor capped so a hand-edited `u64::MAX` cannot lock publish (#135).
- Also on `main`: `front_door` scope for paired apps after owner grant (#140).

### Owner / CLI
- `konsensus sign-challenge` matches the `/auth/token` challenge format used by owner-token flows (#125).
- Also on `main`: one-step owner grant with a short owner code (#145).

### Demo / honesty
- One-command **regtest rehearsal** for local demos (#122); **rehearsal v2** adds front-door, voice-note, and 1:1 call beats (#134).
- **No mock-proof profile** envelope on real Lightning backends (#123).

### Exactly-once

- Instant paid first contact and payer-side reply acceptance (#102, #100).
- Pre-payment compose failures release to `released` when proven unpaid (#144).

### Readiness

## Config, API, protocol migration and rollback

The [rc7 → rc8 upgrade guide](../UPGRADING.md) is the migration checklist and
complete new-config inventory. **Esplora remains the default** unless the owner
selects `bitcoind` or `electrum`; this release does not switch existing nodes or
supply an onboarding selector.

New keys include `[chain]` Core `rpc_host`, `rpc_port`, `cookie_file` (or
`rpc_user` + `rpc_password_file`), Electrum `server_url` and `operator`;
top-level `disk_free_floor_bytes`; `[privacy] peer_exchange`, `shareable_peers`,
`share_peer_labels`; `[remote_access] listen_addr`, `advertised_endpoint`;
`[network] advertised_addr`, `stun_server`; `[calls] stun_listen`;
`[pricing] call_msat`; `[identity] hosted`; routing-fee, LSPS2 and sponsor policy
keys. The guide lists their defaults and constraints. The existing porch price
keys now default to 1000 msat and advertised/effective porch reads obey that floor.

App migration must handle:

- Flat optional balance fields: `onchain_spendable_sats`, `onchain_total_sats`,
  `anchor_reserve_sats`, `lightning_spendable_sats`, `closing_sats`,
  `contested_sats`. `balance_msat` remains the legacy aggregate. Missing means
  unknown; categories overlap and must not be summed into a wallet total.
- Owner status `chain_view.{backend,trust_level,host}` and nullable `chain_sync`.
  **`own_node` replaces `trustless`**; Electrum uses it only with `operator = "own"`
  (default `third_party`). Ownership is configured, not verified. A stalled
  diagnostic has `state`, `since` (Unix seconds), `last_error_kind: "sync_failed"`.
  Null is not proof of sync; `money_ready` remains the readiness signal.
- Optional **`fee_paid_msat`** on compose/operation, pay/keysend and payment-status
  results: actual settled outgoing LDK fees only, aggregate when every component
  is known. Missing does not mean zero. `max_routing_fee_msat` stays a ceiling;
  fees do not establish settlement or retry permission.
- Owner status disk fields (`disk_low`, `disk_free_bytes`,
  `disk_free_floor_bytes`), `custody_mode`, endpoint/STUN metadata, scoped
  pairing/owner grants, all-in caps and journaled compose states.
- Capability-gated `room_binding_v1`, `porch_read_v1`, `call_meeting_v1`; paid
  peer-exchange quote/redemption in place of unpaid discovery; Noise tunnel
  framing and transport-key pinning. New node APIs do not imply app UI support.
- Removed unbound invite routes return `410` / `legacy_invite_removed` (#151).
  Apps use invitee-bound `/api/v1/invites` and `/api/v1/invites/accept`;
  introduction routes remain for sponsor kits, deprecated as profile surfaces.

Numbered schema migrations since rc7 (all under
`crates/konsensus-storage/migrations/`):

| File | Protocol/state effect | Rollback constraint |
| --- | --- | --- |
| `020_pending_delivery_state.sql` | Paid delivery dispatch/state (#103) | Preserve queued paid work and dispatch evidence. |
| `021_paid_delivery_rejections.sql` | Paid rejections, retry timing, receipt acceptance (#103) | Preserve acceptance tombstones and retry state. |
| `022_receipt_bindings.sql` | Duplicate acceptance ACK binding (#103) | Keep proof bindings after content retention. |
| `023_delivery_price_quotes.sql` | Durable recipient quotes (#103) | Keep quote validity and expiry evidence. |
| `024_outbox_operations.sql` | Exactly-once compose journal (#113) | Keep operation/payment identities; loss risks duplicate payment. |
| `025_outbox_recovery.sql` | Recovery accounting/compaction markers (#116) | Keep replay tombstones and accounting state. |
| `026_outstanding_web_requests.sql` | Durable bound web replies (#132) | Keep one-use paid request/response authority. |
| `027_call_state.sql` | Call lifecycle/replay reservations (#131) | Keep burned call IDs and pending operations. |
| `028_call_request_hold.sql` | Request-bound call holds (#131) | Keep unfinalized signals hidden until admission/recovery. |

PostgreSQL applies the same numbered versions: dedicated dialect files are
`postgres/021_paid_delivery_rejections.sql`, `postgres/024_outbox_operations.sql`,
`postgres/025_outbox_recovery.sql`; 020 is inline in the runner and the others
reuse common SQL. No numbered migrations were added after `5cf12a5`.

**No down migrations are shipped. Do not run rc7 against migrated state.**
Restoring a pre-upgrade directory is only a rollback option before the first
LDK start on rc8; afterward roll forward with current state. Protocol changes
also persist outside SQL: pairing/device/owner keys, encrypted seeds, delivery
and fee-recovery evidence, front-door sequence floors, and `STATE_GENERATION`
(generation 1). Keep their current state together. Older binaries cannot be
assumed compatible, and pre-guard binaries cannot enforce the generation check.
The marker cannot detect a whole-directory stale restore. Rooms use encrypted
ordinary chat; Browse caches are memory-only; peer-exchange quotes are stateless
but remain redeemable until expiry with the same identity. Disabling opt-ins
cannot undo settled payments, issued quotes or existing authorizations.

## Human release checklist (tag → sign → publish)

Per [`docs/ops/RELEASE_POLICY.md`](../ops/RELEASE_POLICY.md): public releases require a **protected signed tag** (not a plain annotated tag).

1. Merge this branch to `main`; record the merge commit as `SOURCE_SHA`.
2. **Signed tag only** (release key `B299274C200301714DC6F51A7C2D6F8AC842EF6E`):

```bash
git fetch origin main && git checkout SOURCE_SHA
git tag -s -u B299274C200301714DC6F51A7C2D6F8AC842EF6E v0.3.0-rc8 -m "BitSov v0.3.0-rc8"
git push origin v0.3.0-rc8
```

3. Wait for CI `release-cli` on `refs/tags/v*` (five `bitsov-*` binaries + `.sha256` + SBOMs → DRAFT prerelease).
4. Assemble `SHA256SUMS` from the five `*.sha256` files; verify each binary; detach-sign with the same release key; upload `SHA256SUMS` + `SHA256SUMS.asc`.
5. Verify the protected tag, Linux artifact, signed checksums, SBOM and artifact attestation/provenance required by release policy. After operator sign-off, paste this file as the release body (fill Source SHA) and publish the GitHub pre-release. Draft CI assets alone are not publication approval.


## Known limits in this release
- **macOS and Windows binaries are not notarized or Authenticode-signed.** Covered by signed `SHA256SUMS` only; Gatekeeper/SmartScreen will block by default.
- **Startup selection is not continuous runtime failover.** Explicit Core/Electrum configurations never fall back to Esplora; Esplora remains the default unless the owner changes it.
- **sqlx 0.8.0 island** still pinned by ldk-node; see `.cargo/audit.toml` / #59.
- **Calls** are a regtest prototype: signalling is paid; media is direct WebRTC; no TURN; STUN is optional (`[calls] stun_listen` off by default; app URL owner-confirmed).
- **Browse** is node-side card/text reading only; no binary media, persistent cache or peer card relay. **Rooms** are fixed-roster ordinary chats, not the broader epoch/role design. **Remote access** needs compatible app Noise framing and key pinning.
- **Disk probing** currently requires Unix; probe failure refuses new money work even if the reserve is zero. Windows artifact availability does not establish operational support.
- **Electrum** remains server-trusting even for `operator = "own"`; neither `own_node` nor a reachable tip proves validation, ownership or synchronization.
- **`money_signer` / `remote_signer` custody modes** are reserved / design-only (#154); hosted VMs should be labeled hosted custody honestly.
