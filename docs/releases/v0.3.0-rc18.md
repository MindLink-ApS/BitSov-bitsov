# BitSov v0.3.0-rc18 — operator signing checklist

**Pre-release.** Not for production use. rc18 = rc17 (`ce7fb53`, tag
`v0.3.0-rc17`) plus six merged PRs. This preparation does not sign, tag or publish.

## Scope

| PR | Change | Operator impact |
|---|---|---|
| #321 (`c5191a2`) | Encrypted-seed `node-id`, configured funding-address network, Read scope for peers/export | `node-id` accepts the same password sources as `sign-challenge`; signet funding addresses are reported as signet. |
| #322 (`79022a7`) | Live owner-console `konsensus peer add` | With `--owner-control`, persist, whitelist, dial and supervise contacts without restart. Matching `[[peers]]` config entries still win at restart. |
| #323 (`4d1942b`) | T4a starter-channel doctrine | Records the operator-funded starter as an opt-in, exit-able principle-3 departure for signet; the admission floor remains unchanged. |
| #324 (`ac4e311`) | Peer admission hardening | Persist before changing live state; serialize mutations with deletion, dial outside the registry lock and reject invalid peer addresses/labels. Audit labels are plaintext metadata. |
| #326 (`735105e`) | Option-A N1/N4/N5: opt-in pushes and bounded reserve trust | Optional owner API `push_sats` and provider `trust_no_reserve`; waiver only for selected-provider inbound channels funded with at most 200,000 sats each. No automatic onboarding opens or mainnet policy approval. |
| #327 (`59c7e85`) | Peer admission gaps and reserve-trust docs | Reject broadcast dial targets, preserve inbound-only re-adds, clarify per-entry import/no-overwrite behavior, per-channel reserve cap, force-close broadcast and fee-bump fallback. |

Release metadata: all 14 workspace packages report `0.3.0-rc18`, with only their
versions changed in `Cargo.lock`. No third-party dependency update or new SQL,
pairing-store or peer-store schema migration. The optional per-provider
`trust_no_reserve` key defaults to false; existing configs need no edits.
Pairing stays v8: **no downgrade to rc16 or older on a v8 pairing store**;
**no downgrade to rc14 after running with embedded LDK**. See
[rc17 → rc18](../UPGRADING.md#rc17--rc18), including rc17 config rollback.

The reserve cap is per channel, not aggregate per trusted peer, and covers the
full funding amount, not the pushed balance. All outbound and larger inbound
channels retain the normal reserve. Force-close still requests commitment
broadcast; missing live channel details fall back to local fee-bumping.
`push_sats` is capped at half the channel amount, requires unpaired Spend
authority and defaults to no push. Mainnet sizes and policy remain out of scope.

## 4. Beta nodes (bitsov-pi, Umbrel): rc17 → rc18

For each signet beta node, perform the following operator upgrade after the
signed release is verified:

1. Record the current BitSov binary path, rc17 version, config, data directory
   and start/service command. Confirm the node is on signet. Select the artifact
   for that machine's OS and architecture; verify its signature/checksum.
2. Stage rc18 **next to the previous rc17 binary**, retaining the old binary as
   rollback. Check the staged binary reports `konsensus 0.3.0-rc18` before
   changing the service path. Keep the existing data directory and encrypted
   seed; do not re-run `init` or restore historical wallet/channel state.
3. Stop only the BitSov node, switch its binary path to rc18, and restart with
   the same config/data and `start --config … --owner-control`. Preserve any
   other existing startup flags; the owner supplies the encryption password.
   **Never stop, reconfigure or modify the Umbrel's own LND or wallet.** BitSov's
   embedded Lightning state is separate; this upgrade touches only BitSov.
4. Check `konsensus 0.3.0-rc18`, a healthy `/api/v1/health`, the expected node ID,
   existing contacts/channels and signet from the funding-address endpoint.
   Confirm encrypted-seed `node-id` and the owner token flow work. Add a contact
   through the owner console only when intended; an unreachable saved contact
   is retried and does not require a second add.
5. Leave reserve trust and channel pushes off unless explicitly opting into the
   reviewed signet starter path. That path specifies a private 100,000-sat
   channel with 10,000 sats pushed. The acceptor's selected provider must be
   explicitly trusted to use the bounded reserve waiver. This does not enable
   automatic opens, prepaid custodial credit or free message admission.
6. If rollback is needed, stop BitSov, remove any `trust_no_reserve` key before
   running rc17 (it rejects the unknown field), and restore the previous binary
   path using the **latest** retained data. Check normal reserve availability
   if waived channels were accepted. Do not restore an old data snapshot, fall
   back to rc16 or older, or touch Umbrel's own LND/wallet. See
   [rollback to rc17](../UPGRADING.md#rollback-to-rc17).
