# BitSov v0.3.0-rc21 — operator signing checklist

**Pre-release.** Not for production use. rc21 is `main` at a reviewed commit
that includes the app-grant call fixes. It contains everything merged since
rc20 (`v0.3.0-rc20`, `0e10897`), through `5b128b1`. Re-pin the bundled app
node only after a signed rc21 is published and verified. This preparation
does not sign, tag or publish.

## Scope

| Area | PRs | Operator impact |
|---|---|---|
| App-grant call spending | #493 | The owner sees, signs and the grant stores the real per-payment value. Paid messages, files, rooms and admission stay capped at 6 sats (or the signed value when lower). Calls use the signed value and the call's pinned per-block ceiling; the offer has its own cap. A call's hold and offer are reserved together, and every draw re-checks the signed value. Re-issue existing app grants stored at 6,000 msat per payment and size `[calls] max_call_minutes` to fit the budget. |
| Direct-channel payments | #493 | A contact on a usable direct channel is paid with no routing fee when the channel carries the payments. A failed direct payment never falls back to a fee-paying route; call blocks re-check the channel their pinned zero fee relies on. |
| Grant-funded call closing | #498 | The closing signal is paid by the call's grant. Its allowance is reserved from that grant outside the caller's hold consent; refusal leaves the call ended without an owner debit. |

Release metadata: all 14 workspace packages and `Cargo.lock` report
`0.3.0-rc21`; dependency versions are unchanged.

## Migrations

There are no new SQL migrations or pairing-store or peer-store schema
version changes since rc20. Pairing storage remains **v8**. Existing app
grants keep their stored per-payment value until re-granted; there is no
automatic widening. See [rc20 → rc21](../UPGRADING.md#rc20--rc21).

## 2. Dry-run gate, then sign (operator only)

- [ ] Run `scripts/release-sign.sh --dry-run v0.3.0-rc21` on the operator's Mac and investigate any darwin-aarch64 rebuild mismatch; never break-glass under time pressure.

**This gate precedes any real artifact signing.** The line above names the
required dry-run; the current script also requires `<merged sha>` and an
explicit waiver for each non-host target. It requires an **existing signed tag**
and CI draft assets: it will not create a tag in dry-run mode. Thus an untagged
prep cannot yet complete this gate. Initial tag signing, which triggers CI,
is a separate operator prerequisite; it does not approve the CI binaries.
Do not use a normal signer invocation merely to get past this prerequisite:
it would continue toward artifact signing without the completed dry-run.
No tag or key operation is authorized or performed by this preparation.

For an Apple Silicon Mac (`aarch64-apple-darwin`), after the operator has
separately established the reviewed signed tag and draft, the full dry-run is:

```sh
scripts/release-sign.sh --dry-run \
  --accept-unverified-target x86_64-apple-darwin \
  --accept-unverified-target aarch64-unknown-linux-gnu \
  --accept-unverified-target x86_64-unknown-linux-gnu \
  --accept-unverified-target x86_64-pc-windows-msvc \
  v0.3.0-rc21 <merged sha>
```

Each target waiver requires a separate operator decision and recorded rationale;
these flags are not evidence of an independent rebuild. If using a different
host, adjust the waivers to exclude that host. Follow the
[RC template](RC_CHECKLIST_TEMPLATE.md) and
[independent rebuild policy](../ops/RELEASE_POLICY.md#independent-rebuild-gate-h3).

## 4. Beta nodes (bitsov-pi, Umbrel): rc20 → rc21

1. Record the current BitSov binary/version, config, data directory, service
   command and signet network. Let calls end and reconcile pending payments.
2. Take a consistent database backup. No new migrations run for rc20 → rc21;
   retain the latest data and seed, and preserve the existing rollback fences.
3. Verify the signed artifact for the node's OS/architecture; stage rc21 next
   to rc20 and confirm `konsensus 0.3.0-rc21`. Do not re-run `init` or restore
   a historical snapshot.
4. Set `[calls] max_call_minutes` to fit typical app budgets (for example,
   10 minutes for a 500-sat grant at 10 sat/min). Leave room for routing
   fees, the offer and the closing allowance, which is outside the caller's
   hold consent but still reserved from the grant.
5. Stop only BitSov, switch its binary path, and restart with the retained
   config/data and intended owner-control/startup options. **Never stop,
   reconfigure or modify Umbrel's own LND or wallet.**
6. Re-issue each app client's grant with `konsensus grant --op <op>`. Without
   `--per-call` the client's proposed per-payment value is signed (capped at the
   budget); pass `--per-call <sats>` to set the limit explicitly. Existing app grants
   bind calls at their stored 6,000 msat per payment until re-granted. Review
   the value before signing; paid messages, files, rooms and admission remain
   capped at 6 sats (or the signed value when lower).
7. Check version, `/api/v1/health`, node identity, contacts/channels, signet
   status and the grant's stored per-payment value. Rehearse a grant-funded
   call and its closing signal, following [the M6 runbook](../ops/M6-CALL-RUNBOOK.md):
   only the callee needs inbound TCP 9736 and 9735; keep the owner API local.
8. Prefer rolling forward with the retained data. Continue to follow the
   existing [rollback constraints](../UPGRADING.md#rollback-constraints) and
   [rc20 → rc21](../UPGRADING.md#rc20--rc21).
