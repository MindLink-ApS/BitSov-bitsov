# BitSov v0.3.0-rc19 — operator signing checklist

**Pre-release.** Not for production use. rc19 = rc18 (`20c6449e`, tag
`v0.3.0-rc18`) plus ten merged PRs: #330, #332, #333, #334, #335, #337,
#339, #340, #341 and #342. This preparation does not sign, tag or publish.

## Scope

| PR | Change | Operator impact |
|---|---|---|
| #330 (`ef85946`) | Preserve typed channel IDs through funding reconciliation | For LDK, open/list expose decimal-string `user_channel_id`, hex `channel_id` and `funding_txo`; use the user ID as the stable identifier. Other backends retain native IDs and return null for the user ID. Owner status reports the configured network. |
| #332 (`2bc9b94`, implements #331) | Channel-open idempotency | Optional UUIDv4 `operation_id`, advertised by `channel_open_operations_v1`; migration 030 stores operations before dispatch. Retry the same ID and parameters. |
| #333 (`0444cf6`, fixes #325) | Deflake shutdown and unpaid-flood tests | Independent hang guards accommodate slow CI runners. |
| #334 (`6dd277a`) | Settle interrupted channel-open operations | Recording survives HTTP disconnects; retry reconciles crash-left pending operations older than ten minutes without redispatch. Proven LDK pre-dispatch refusals release the ID. |
| #335 (`11e92f3`) | Patch modern WebPKI lines and vendor electrum-client | Updates verifier/root dependencies for RUSTSEC-2026-0381/0382; legacy SQLx/test-only island exceptions remain documented. |
| #337 (`9b0cc05`) | Local permissions, token handling and parser hardening | Dedicated config parent owned by the node user, forced to 0700 or startup refuses; control socket 0600. CORS, trace redaction, WebSocket tokens, amount and signature/invite validation tighten. |
| #339 (`deccf5d`) | H1 Host/Origin local-trust checks | Local token issuance and local-only reads/WebSocket admission resist DNS rebinding; native clients without Origin remain supported. |
| #340 (`4acb57b`) | H2 explicit opt-in for argv secrets | Secret-valued arguments require `--insecure-argv` and still warn; migrate launchers to descriptors/files or prompts. |
| #341 (`6e143cd`) | H3 exact-tag host rebuild before artifact signing | Pinned toolchain/shared recipe, independent host hash comparison, retained mismatch evidence, logged reasoned host break-glass and explicit non-host waivers. |
| #342 (`6b22956`) | Release signatures/assets and LND settlement amounts | Validate VALIDSIG primary field, sign all source assets (17 with the two Darwin toolchain records added by #355), permit safe checksum-upload retries; refuse mismatched settled LND dispatch amounts and amount overflows. |

## 2. Dry-run gate, then sign (operator only)

- [ ] Run `scripts/release-sign.sh --dry-run v0.3.0-rc19` on Rasmus's Mac and investigate any darwin-aarch64 rebuild mismatch; never break-glass under time pressure.

**This gate precedes any real artifact signing.** The line above names the
required dry-run; the current script also requires `<merged sha>` and an
explicit waiver for each non-host target. It requires an **existing signed tag**
and CI draft assets: it will not create a tag in dry-run mode. Thus an untagged
prep cannot yet complete this gate. Initial tag signing, which triggers CI,
is a separate operator prerequisite; it does not approve the CI binaries.
Do not use a normal signer invocation merely to get past this prerequisite:
it would continue toward artifact signing without the completed dry-run.
No tag or key operation is authorized or performed by this preparation.

For an Apple Silicon Mac (`aarch64-apple-darwin`), after the operator has
separately established the reviewed signed tag and draft, the full dry-run is:

```sh
scripts/release-sign.sh --dry-run \
  --accept-unverified-target x86_64-apple-darwin \
  --accept-unverified-target aarch64-unknown-linux-gnu \
  --accept-unverified-target x86_64-unknown-linux-gnu \
  --accept-unverified-target x86_64-pc-windows-msvc \
  v0.3.0-rc19 <merged sha>
```

Each target waiver requires a separate operator decision and recorded rationale;
these flags are not evidence of an independent rebuild. If using a different
host, adjust the waivers to exclude that host. Follow the
[RC template](RC_CHECKLIST_TEMPLATE.md) and
[independent rebuild policy](../ops/RELEASE_POLICY.md#independent-rebuild-gate-h3).

## 4. Beta nodes (bitsov-pi, Umbrel): rc18 → rc19

1. Record the current BitSov binary/version, config, data directory, service
   command and signet network. Reconcile pending channel opens/payments.
2. Check that the config parent is dedicated, owned by the node user and can
   be forced to 0700; check container volume ownership. Update argv-secret
   launchers to fd/file/prompt input. See [upgrade notes](../UPGRADING.md#rc18--rc19).
3. Verify the signed artifact for the node's OS/architecture; stage rc19 next
   to rc18 and confirm `konsensus 0.3.0-rc19`. Retain the latest data and seed;
   do not re-run `init` or restore a historical snapshot.
4. Stop only BitSov, switch its binary path, and restart with the retained
   config/data and intended owner-control/startup options. **Never stop,
   reconfigure or modify Umbrel's own LND or wallet.**
5. Check version, `/api/v1/health`, node identity, contacts/channels and signet
   status/funding address. Verify the encrypted-seed owner-token flow, local
   Host/Origin behavior and migration 030. For LDK, retain the decimal-string
   `user_channel_id`; use native channel IDs for other backends. Reuse operation
   IDs for retries; inspect uncertain outcomes before new attempts.
6. Keep existing signet reserve/trust policy: inbound/JIT channels require
   anchors plus reserve or the selected-provider waiver for at most 200,000
   sats per channel. Recovery verification needs the same reserve or waiver.
7. Prefer rolling forward on failure. rc18 lacks migration-030 operation
   tracking/reconciliation; do not blindly roll back and replay requests.
   Preserve latest state and follow [rollback constraints](../UPGRADING.md#rollback-constraints).
