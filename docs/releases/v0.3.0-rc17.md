# BitSov v0.3.0-rc17 — operator signing checklist

**Pre-release.** Not for production use. rc17 = rc16 (`8c6565f`) plus three
merged PRs. This preparation does not sign, tag or publish.

## Scope

| PR | Change | Operator impact |
|---|---|---|
| #317 (`0dc7307`) | `konsensus sign-challenge` decrypts an encrypted `mnemonic.enc` (terminal prompt, `--password-fd`, `--password-file`, `--password`); `docs/ops/owner-token.sh` forwards the same sources | The owner can now mint the full-scope token from `/api/v1/auth/token` on encrypted-seed nodes. On rc16 this was impossible, so `open-channel`, `send-onchain`, `close-channel`, `/peers` and `/invites` were unreachable on encrypted nodes. |
| #312 (`b313055`) | `relation_envelope_id_v1`: a fresh random `envelope_id` per accepted contact relation intent; pairing storage **v8** | **Forward-only.** After rc17 writes `pairing/clients.json` as v8, rc16 and older refuse it. See [rc16 → rc17](../UPGRADING.md#rc16--rc17-pairing-storage-v8). |
| #316 (`d3e9640`) | Docs: the enforced 1,000 msat admission floor (LAW 02) | None |

Release metadata: all 14 workspace packages report `0.3.0-rc17`, with only their
versions changed in `Cargo.lock`. No third-party dependency, SQL migration or
config key changes. The rc15/rc16 rollback rule still holds: **no downgrade to
rc14 after running with embedded LDK**, and with v8, **no downgrade to rc16 after
running rc17**.

Known gap, not a release blocker: `konsensus node-id` still reads the mnemonic
without a password, so it fails closed on `mnemonic.enc`. The node id is in
the startup log (`node built node_id=…`).

## 4. Beta nodes (bitsov-pi, Umbrel)

Both run rc16 on signet with encrypted seeds. Per node: verify the signed
binary, stop the node, replace the binary, keep the data directory, and start
it again with the same `start --config … --owner-control`; the owner types the
password. Expect `konsensus 0.3.0-rc17` and a healthy `/api/v1/health`. After
that the owner can mint an owner token (`docs/ops/owner-token.sh`) and open the
signet channel between the two nodes.
