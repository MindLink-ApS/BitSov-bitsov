## What changed on main since the last payments pass

`REVIEW-2026-11-02` reviewed `b3f1ad1`. Thirty-six commits have landed. `git diff b3f1ad1..90e855f` does not touch `crates/konsensus-lightning/src`, `crates/konsensus-api/src/handlers/payments/`, `crates/konsensus-api/src/spend_budget.rs`, or the subsidy and auto-channel openers. The commits that move a payment, a hold, a fee figure, or a payee check:

- `64d35c1` (`#503`) — the invoice payee is compared with `eq_ignore_ascii_case` in `invoice_payee_is`. Both `create_payment_proof_via_invoice` and `validate_admission_invoice` use it. A different payee is still refused before `pay_invoice`. This is the Low that review fixed. It is on main. Re-read here; not opened again.
- `7e04383` (`#513`) — `proven_unpaid` no longer treats another operation's admission-journal attempt as evidence that this send paid. The attempt's dispatch, settlement, and envelope are not read, and the wallet is not asked about that hash. `draft` still copies the peer's latest attempt hash onto the row; that hash is skipped when it belongs to another operation. This operation's own attempts, attempts with no operation link, an unreadable journal, a hash no attempt accounts for, and a wallet that cannot answer still fail closed. The same operation does not dispatch again.
- `9c923c9` (`#521`) — `POST /api/v1/files/:id/send` adds optional `fee_paid_msat`. On the LDK backend it is the debit's recorded fees plus any re-admission's, combined with `checked_add`. It is omitted when a component is unknown, on overflow, and on every other backend. `amount_msat` and `max_routing_fee_msat` are unchanged. The grant still settles through `Debit::settled` and `settled_total`, which keep an unknown fee as the whole ceiling.
- `5179ed9` (`#519`) — a session encrypt that cannot be saved returns `NotPersisted` and withholds the ciphertext. Message and file payment run only after that encrypt. A failure there releases a debit that has not dispatched. A failure after a settled admission goes through `FirstContactCharge::error`, which settles the admission instead of releasing it. A room member that cannot be saved is skipped before `create_metered_payment_proof`, with amount 0.
- `c5d2ce9` (`#514`) — `prepare_call_block_invoice` refuses while this node has no session with the caller, or while that session is marked for renegotiation, before `create_invoice` and again after it. No bolt11 is returned in that case, so the caller is not given an invoice to pay. A paid block this node cannot read is still burned at the gate. For the higher node id the reject reason is the existing terminal `undecryptable:` prefix, which the sender records as `failed_paid`. Call settlement already treats `failed_paid` as paid, and `draw_call_spend_for_grant` still refuses a sequence already paid or in flight.
- `f77701f` (`#495`) — paired call media is bound to the client that committed the invite or answer. `owns_call_spend` now matches client id, epoch, and fingerprint. A hold alone does not grant media. The binding is memory only and is gone after restart. Draws still go through `draw_call_spend` on the grant that reserved the hold. The map stops at `MAX_OPEN_CALLS` (4096).
- `dae1ce2` (`#507`) — authenticated `GET /api/v1/status` reports `[calls] max_call_minutes`. `PublicHealthResponse` is a different struct. `call_max_minutes` still prefers the hold's pinned cap over the live setting.

`3fb5ac9` (`#481`) decays routing weights by block height. It does not change a fee ceiling, an invoice amount, or a channel capacity. `4723f93` and `b884924` count and cap call-media packets. They do not move a balance. `ad49727` is an end-to-end grant test. `90e855f` (`#489`) is the owner-API note already merged; its code is the claim-code and seed path, not a debit.

## Info

**I1 — A new call hold is still checked against the largest active channel on the node.** `with_new_call_spend` (`crates/konsensus-api/src/calls.rs`). Same note as I1 in the 2026-11-02 report. That function did not change. The grant total, the per-block ceiling, and the routing ceiling still bind what is paid.

**I2 — LDK channel capacity and the punishment reserve still multiply sats by 1000 with `*`.** `channel_info` (`crates/konsensus-lightning/src/ldk.rs`). No lightning source file changed in this range. The 2026-11-02 note stands.

**I3 — The file-send fee field is a report, not a second ledger.** A client that treats a missing `fee_paid_msat` as zero would under-count. The field is omitted precisely when the fee is not known, which is the same rule the room path already uses. The grant does not read this response.

## Checked, not a finding

- Channel open still rejects `amount_sats` above `u64::MAX / 1000`, rejects `push_sats` above half the capacity, and converts push with `checked_mul(1000)`. Close and force-close still require `ScopedAuth<Spend>`. No production change in that handler since `b3f1ad1`.
- Pay and keysend still require `request_id`. A repeat does not dispatch. The grant hole on a late terminal result is M1, not a new path.
- `proven_unpaid` after #513 still returns false when this operation's row shows a dispatch, a pending admission, a settlement, a proof, a non-zero admission or readmission amount, or a payment hash. An attempt linked to this operation, or to nobody, still fails the check on `dispatch_started`, `message_may_have_dispatched`, an envelope, a settlement time, or a reported readmission. Those hashes are still looked up, and any answer other than `PaymentNotFound` is not proof of nonpayment.
- `Operation::dispatch` still sets `dispatched` and saves the row before the wallet future is polled. A later failure of that operation cannot be proven unpaid.
- `deliver_settled_admission` still replaces the journal head and drops `previous_attempt`. The settled attempt keeps the paying operation's link. #513 does not treat that head as this send's payment when the link is another operation. The tests added with #513 cover a send refused before paying, a minute refused before dispatch, a row left `prepared` with the older hash copied on, and a lost wallet reply that stays `payment_unknown`.
- Call-block draws still refuse a price or fee above the pinned per-block ceiling, a sequence at or past the hold's `max_call_minutes`, and a sequence already paid or drawn. Closing draws still use `u32::MAX` and must fit `closing_allowance_msat`. None of that arithmetic changed.
- A direct-channel send still passes a zero routing ceiling through as `Some(0)` / `fee_limit_msat`, not as an omitted limit. LNbits still has no fee-limited pay and returns `PaymentNotDispatched`.
- `invoice_payee_is` is full-string equality aside from ASCII case. `handle_lightning_info_received` still requires 66 hex characters, a `02` or `03` prefix, and a successful `hex::decode` before the key is stored. Digits have no case, so an uppercase key still has to be that same compressed key.
- `from_encrypt_failure` does not run a payment. The file sender releases its debit on that error before `create_metered_payment_proof`. Compose does the same when no admission has settled.
- `remember_call_client` runs only after `reserve_outgoing` has taken the call, and only for an invite or an answer. A second operation cannot reserve that signal (`Replayed` or `InFlight`) and therefore cannot replace the pending binding. `commit_call_client` refuses a pending entry whose operation id or request hash does not match, before the call row is published.
- `owns_call_media` does not create a hold and does not draw one. A restarted process has no binding, so media fails closed. Spend recovery stays on the grant file.
- Authenticated status exposing `max_call_minutes` does not change `reserve_call_at` or `draw_call_spend_for_grant`. The public health route does not use `HealthResponse`.
- No new `unwrap` on a peer-supplied amount in the payment diff. Fee sums that can overflow use `checked_add` and omit the report, or `saturating_add` on a ceiling that was already a ceiling.
