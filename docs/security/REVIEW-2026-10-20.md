# Security review — 2026-10-20

Signet beta, heading toward a public beta. Reviewer pass over the owner-control API, listeners, secret handling, peer parsers, channel and payment bounds, the release-signing path, data-directory permissions, and `cargo deny` / `cargo audit`.

This file lives in the private repository. It is not a public advisory. No GitHub issues were opened.

## High and Critical — not fixed here

**0 Critical. 3 High.** These need a design choice or a protocol/release-process change. The patches in this PR do not attempt them.

| ID | Severity | One line |
|---|---|---|
| H1 | High | `POST /api/v1/auth/local` trusts loopback TCP and ignores `Host`, so a DNS-rebinding page can mint a `read`+`receive` JWT (including message plaintext). |
| H2 | High | `--password` and `--mnemonic` put secrets on the process command line. `/proc/<pid>/cmdline` is mode `0444` on a typical Linux host, so another local user can read them for the life of the process. |
| H3 | High | `scripts/release-sign.sh` GPG-signs the CI draft's binaries after a checksum match. It does not rebuild those bytes from the tagged source, so a compromised CI can ship a malicious binary the release key then attests. |

### H1 — Loopback token mint has no Host allowlist

`crates/konsensus-api/src/handlers/auth_routes.rs:176` (`issue_local_token`). The only admission check is `ConnectInfo` `ip().is_loopback()` at lines 181–189. The default API bind is `127.0.0.1:3141` (`crates/konsensus-node/src/config.rs:2104`).

The LAN setup page already refuses a `Host` that is not one of its own addresses (`crates/konsensus-api/src/bootstrap/setup.rs:188`). The owner API does not.

**Exploit sketch.** A page on an attacker-controlled name with a short DNS TTL loads script, then the name is changed to `127.0.0.1`. The browser sends `POST /api/v1/auth/local` to port 3141. The TCP peer is loopback, so the node mints `Scope::loopback_only()` (`read` + `receive`, 24h). From the browser's point of view the request is same-origin, so CORS does not hide the body. `read` includes `GET /messages/:id/plaintext` (`docs/security/AUTH_SCOPES.md:59`). The WebSocket upgrade refuses an unpaired local token (`crates/konsensus-api/src/ws.rs:50`), so this is the REST history, not the live socket. Spend, admin, and identity scopes are not in this token. Browsers that enforce local-network access (current Chrome) may prompt or block the second connection; Firefox and older clients may not. The setup page's Host check exists because that gap is real.

**Fix (not applied).** Before minting, require exactly one `Host` whose value is `127.0.0.1:3141`, `localhost:3141`, or `[::1]:3141` for the port actually bound, and reject anything else with 401. Do not add a general reverse-proxy Host middleware: operators who front the loopback port with a name would need an explicit allow entry. Rate limiting (`auth_local`, 5/min) does not stop a single successful mint.

### H2 — Secrets on argv

`crates/konsensus-node/src/cli.rs:84` (`start --password`) and `crates/konsensus-node/src/cli.rs:189` (`restore --mnemonic`). The same `--password` flag exists on `node-id` and `sign-challenge`.

**Exploit sketch.** `konsensus start --password '…'` or `konsensus restore --mnemonic 'word …'` keeps those strings in `/proc/<pid>/cmdline` until exit. On this review host that file is mode `0444`. A different uid that cannot `ptrace` the node can still read the encryption password or the 24-word seed. `--password-fd` and the interactive prompt already avoid this (`docs/operations/password-input.md`, `crates/konsensus-node/src/password.rs`).

**Fix (not applied).** For the public beta, reject `--password` and `--mnemonic` unless an explicit break-glass flag is set, and keep `--password-fd` / the prompt / a mnemonic file. Scrubbing argv after parse needs a libc write over the process's own argument memory and is easy to miss on a thread that has already copied the `String`. Removing the flags outright is a CLI break; do it on a major boundary, not inside this review.

### H3 — Release signature attests CI output

`scripts/release-sign.sh:68` downloads each draft asset, checks the sibling `.sha256` (lines 69–74), then detached-signs `SHA256SUMS` with `B299274C200301714DC6F51A7C2D6F8AC842EF6E` (lines 78–80). The tag is checked against the commit the operator named. The script never compiles that commit.

**Exploit sketch.** An attacker who can publish the tag's CI artifacts (stolen CI credentials, a poisoned builder) uploads a backdoored `bitsov-linux-x86_64` plus a `.sha256` of that file. The operator's script matches the checksum, signs it, and attaches `SHA256SUMS.asc`. Users who trust the release key install the CI binary. The signature does not prove the binary is the source at the tag.

**Fix (not applied).** On the signing machine, rebuild each target from the tagged commit (or a recorded rebuild) and require a byte-for-byte match before `gpg --detach-sign`. Until then, treat the signature as "the operator saw these CI bytes," not "these bytes are that commit." This is a release-process change, not a node patch. `docs/ops/RELEASE_POLICY.md` should say so in the same words.

## Threat model

The attacker classes that matter for this beta:

1. **Remote peer.** Speaks Noise after a 64-byte pre-noise cookie (`crates/konsensus-message/src/transport/cookie.rs`). Frames are length-prefixed, capped at 16 MiB, and the length is checked before the body is allocated (`crates/konsensus-message/src/wire.rs:1130`, `crates/konsensus-message/src/transport/mod.rs` `read_bounded_message`). Custom serde visitors cap keys, ratchet payloads, capabilities, and price maps. Property tests in this PR hammer `decode_frame`, introduction links, invite tokens, BSX documents, and STUN datagrams.
2. **Browser or other loopback client.** Default API is `127.0.0.1:3141`. `/auth/local` is the trust boundary (H1). Paired tokens are binding-checked every request. `ScopedAuth<Spend>` refuses paired callers on unmetered money routes; budgeted paired spend goes through `MeteredSpend`.
3. **Another local uid.** Unix socket `data_dir/control.sock` is the owner channel (grants, identity replacement). Same-uid sidecar access is a documented limitation (`crates/konsensus-api/src/control.rs` module comment). Other uids were the bind/chmod race fixed below.
4. **Operator supply chain.** Release key, `deny.toml` advisory gate, vendored LDK. See H3 and the dependency section.
5. **Malicious or buggy owner client.** Channel open, on-chain send, and close are owner-key only. A zero `amount_sats` used to dial the peer before the backend rejected it. That dial is now refused in the API.

What this pass did **not** find: an unauthenticated remote spend, a seed leak in logs from the password-fd path, a frame parser that allocates from the length prefix before the cap, or a new unignored RUSTSEC vulnerability.

## Medium — fixed in this PR

### M1 — Control socket was reachable while the data directory was traversable

`crates/konsensus-api/src/control.rs:915`. Bind used `UnixListener::bind` and then `chmod 0600`. With umask `022` the inode is `0644` until chmod. `create_dir_all` leaves the data directory `0755`, so another local uid could `connect()` in that window and send commands that do not carry a confirmation phrase (`AddPeer`, `Revoke`, `OpenWindow`, `RevokeGrant`, `Status`).

**Fix.** `ensure_owner_private_dir` (`crates/konsensus-api/src/pairing.rs:4195`) forces `0700` and fails if group/other bits remain. `ControlServer::bind` calls it **before** bind, then sets the socket to `0600` and removes it if that mode does not stick. `init`, `restore`, `start`, and first-run bootstrap call the same helper (`crates/konsensus-node/src/main.rs`, `crates/konsensus-node/src/cli/owner.rs`). `owner_control_socket_permissions` starts from mode `0755` and requires `0700` on the directory and `0600` on the socket.

A filesystem that ignores `chmod` now fails closed instead of serving. This removes group access to the seed directory on purpose.

### M2 — HTTP traces included `?token=`

`crates/konsensus-api/src/lib.rs:209`. `TraceLayer::new_for_http()` records the full URI. WebSocket clients may still pass `?token=`.

**Fix.** The span is `method` plus `uri.path()` via `traced_http_request` (`lib.rs:234`). `http_trace_omits_query_token` locks that a query JWT is absent.

### M3 — CORS list accepted `*` and `null`

`crates/konsensus-api/src/lib.rs:238`. `KONSENSUS_CORS_ALLOWED_ORIGINS` was any non-empty header value. `null` is a real browser `Origin` (sandboxed iframe). A literal `*` is not a wildcard in tower-http's list match, but it is the string operators set when they mean "anyone."

**Fix.** `cors_origin_token_ok` drops `*`, `null`, and `NULL`. Other origins are unchanged. `cors_rejects_wildcard_and_null_origin` covers it. An environment that set only `*` now allows no cross-origin browser reads.

### M4 — WebSocket query token replaced the subprotocol token

`crates/konsensus-api/src/ws.rs:80`. When both were present, `?token=` won. A logged or injected query could select a different credential than the header the client set.

**Fix.** `bitsov.jwt.` wins when it is present. Query-only clients still work (`extract_ws_token_accepts_query_when_subprotocol_is_absent`). Removing the query form entirely is a client break and is not in this PR.

### M5 — Channel open of 0 sats dialed the peer first

`crates/konsensus-api/src/handlers/payments.rs:925` calls `validate_channel_amount_sats` (`payments.rs:877`) after an idempotent replay and before `require_money_ready` or any Lightning dial. `ChannelLimits` treats `requested > max` as the failure, so `0` passed and `open_ldk_channel_with_policy` (`crates/konsensus-lightning/src/ldk.rs:3062`) parsed `peer_addr` and connected. The route is owner-key only (`ScopedAuth<Spend>`). `peer_addr` is a `SocketAddr`, so it is not a DNS name, but it can be a link-local or other local literal.

**Fix.** Amounts outside `1..=u64::MAX/1000` return `not_dispatched` and never dial. The per-channel LDK cap is still enforced in the backend; this patch does not duplicate it. A recorded operation with the same id still replays from storage and does not dial again.

### M6 — Invite tokens ignored a trailing suffix; Ed25519 checks were ZIP-215

`InviteToken::parse_bytes` (`crates/konsensus-core/src/invite.rs:476`) treated the last 64 bytes as the signature and ignored a suffix. `BitSovInvite::verify`, the message gate (`crates/konsensus-core/src/gate.rs` `verify_signature`), and federation `SignedMessage::verify_signature` (`crates/konsensus-core/src/federation.rs`) used `Verifier::verify` rather than `verify_strict`.

**Exploit sketch.** A token with extra bytes after a valid signature still parsed, which is the wrong length for a fixed encoding and complicates any future byte-identity cache. A non-canonical `S` (ZIP-215) verifies under `verify` and fails `verify_strict`. Honest `ed25519-dalek` signatures are canonical, so this does not break current issuers. Replay for invites is the nonce, and envelope ids are `blake3(ciphertext || nonce)`, so malleability was not a second payment. It was still the wrong verifier next to code that already uses `verify_strict` (introduction, sponsor, front door).

**Fix.** Exact length, `TrailingBytes` on a suffix, and `verify_strict` at those three sites. `trailing_bytes_rejected` covers the suffix. `NodeIdentity::verify` is unchanged (Low, below) so this stays a local swap.

## Medium — open

### M7 — Mnemonic mode is a warning

`crates/konsensus-node/src/config.rs:1634`. `validate()` logs when `mode & 0o077 != 0` and continues. `write_mnemonic` creates the file `0600`, but a copied or restored file can be `0644` and the node still unlocks it.

**Exploit sketch.** Another local user reads `mnemonic.txt` if the operator (or a backup tool) left it group/world-readable. The data directory is now `0700` (M1), which hides the file from users who cannot traverse the directory. A process that can traverse it, or a mnemonic stored outside the data directory, still depends on the file mode.

**Fix (not applied).** On start, if the mode is loose, `chmod 0600` and refuse to continue when the bits remain. Do not put that failure inside `NodeConfig::validate()`: many unit tests `fs::write` a mnemonic and then expect a different error (port collision, owner-verifier refusal). A start-only check needs those fixtures updated on purpose.

### M8 — Non-loopback API is legal when remote access is off

`crates/konsensus-node/src/config.rs:1655` refuses a non-loopback `[api].listen_addr` only when `[remote_access]` is set. With remote access unset, `0.0.0.0:3141` is accepted. The default remains `127.0.0.1:3141`.

**Exploit sketch.** An operator who sets the API to an unspecified address exposes unauthenticated `GET /metrics`, `GET /api/v1/health`, `GET /api/v1/auth/challenge`, and the pairing routes to the network. `/auth/local` still requires a loopback source address, so a remote TCP peer does not receive a JWT. Challenge issuance is not a token. Metrics and health are the leak.

**Fix (not applied).** Refuse a non-loopback API address unless an explicit `allow_public_api` (name TBD) is set. Do not silently change operators who already bind `0.0.0.0`.

### M9 — Envelope `references` are not signed

`UkmEnvelope::signable_bytes` (`crates/konsensus-core/src/envelope.rs:114`) covers kind, sender, recipient, timestamp, ciphertext, nonce, and the payment proof. It does not cover `references` (`envelope.rs:88`) or `id`. The comment on that function says the signature should stand on its own for the payment proof, and that Noise is the transport defense.

**Exploit sketch.** A forwarder that can rewrite the envelope outside the Noise session (a store-and-forward that keeps the signed object, or a bug that re-serializes it) can change threading, replies, and reactions without invalidating the signature. Ciphertext and payment proof stay bound.

**Fix (not applied).** Add `references` to the signed bytes under a new envelope version. Doing it in place rejects every existing signature. That is a protocol change, not a patch in this PR.

## Low

### L1 — `jwt_secret` is a `String`

`crates/konsensus-api/src/state.rs:98`. `derive_jwt_secret` returns `Zeroizing<[u8; 32]>`, then the value is stored as a `String` for the process lifetime. The seed is already in process memory on an unlocked node. A core dump or swap of the API state includes the HMAC key in a form `Zeroizing` will not wipe.

**Fix.** Store `Zeroizing<String>` or a fixed zeroizing array. Confirm `Debug` on `AppState` does not print it (it must not).

### L2 — `NodeIdentity::verify` is not strict

`crates/konsensus-core/src/identity.rs:298` still calls `verify`. Gate, federation, and invite tokens now use `verify_strict` (M6). Callers that go through `NodeIdentity::verify` still accept a non-canonical `S`. Honest signatures are canonical.

**Fix.** Switch this method to `verify_strict` once every caller is known to use dalek signatures. It was left alone to keep M6 a three-site change.

### L3 — Chain fallbacks may be `http`

`crates/konsensus-chain/src/bearer.rs:345`. The OAuth token URL must be `https` (line 246). Fallback esplora endpoints may be `http` or `https`. That is operator configuration. An `http` fallback on an untrusted network is a chain-data downgrade.

**Fix.** Default the fallback list to `https` only, and require an explicit flag for `http`.

### L4 — Frame strings are capped by the 16 MiB frame, not a field limit

`decode_frame` rejects a length above `MAX_FRAME_BYTES` before parsing (`wire.rs:1140`). Individual strings inside a legal frame (`reason`, `sdp`, `bolt11`, and similar) are not separately capped. A peer can send one 16 MiB frame. Connection and rate limits bound how often.

**Fix.** Add per-field limits in the serde visitors the way keys and price maps are already capped. Do not lower `MAX_FRAME_BYTES` without a protocol note.

### L5 — Legacy WebSocket `?token=` remains

After M2 and M4 the query cannot override a subprotocol token and is not written into the HTTP span. It is still accepted when it is the only credential, so access logs outside this process (a reverse proxy on the loopback port) can still record it.

**Fix.** Stop reading `?token=` once shipped clients send `bitsov.jwt.` only.

## Dependency scan

Ran on this tree after `git fetch origin main` (`11e92f3`):

- `cargo deny 0.20.2 check advisories` — **ok**, using `deny.toml` (all-features, the reviewed ignore list).
- `cargo audit 0.22.2` — no vulnerability findings. One allowed warning: `paste` 1.0.15 is unmaintained (`RUSTSEC-2024-0436`).

The ignore list is pre-existing debt, not a silent pass. The items that still matter:

| Advisory | Residual | Rank |
|---|---|---|
| `RUSTSEC-2024-0363` sqlx 0.8.0 | Protocol smuggling needs a bound parameter larger than 4 GiB. Wire frames cap at 16 MiB and the API at 2 MiB. Postgres is compiled in. Recheck if those caps move. | Low while the caps hold |
| `RUSTSEC-2026-0381` / `0382` (and the other rustls 0.21 / webpki 0.101 entries) | Legacy Postgres TLS can accept a chain through a distrusted emSign intermediate. The default SQLite node does not open that stack. A Postgres-over-TLS deployment can. | Medium for Postgres TLS only |
| `RUSTSEC-2026-0367`–`0369` zip 0.6 | Test harnesses only; not in the shipped binary. | Low |
| `RUSTSEC-2024-0436` paste | Unmaintained proc-macro. No known vulnerability in this scan. | Low |

**Fix for the rustls 0.21 island.** Bump ldk-node so the `sqlx = "=0.8.0"` pin can move. That is the same island called out in `deny.toml` and `docs/security/supply-chain-audit-scope.md`. Not a one-file patch.
