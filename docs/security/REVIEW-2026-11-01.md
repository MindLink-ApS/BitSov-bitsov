## Medium — fixed in this PR

### M1 — A call-block invoice was minted before the binding cap, for any amount

`prepare_call_block_invoice` (`crates/konsensus-node/src/session_handler.rs`). A privileged peer with a live, due call asks for a block invoice with `RequestInvoice`. The purpose names the call id and sequence. Before this PR the handler validated the call, then called `lightning.create_invoice(amount_msat, …)` with the peer's amount, and only then inserted the payment hash. `record_call_block_invoice` refuses a ninth binding for that peer, call, and sequence (`MAX_CALL_BLOCK_INVOICES` = 8). The wallet call had already run.

`amount_msat` is the peer's `u64`. Zero and values above the owner invoice ceiling were forwarded to the backend. The payment gate still requires this node's kind-404 price before a block is admitted, so a cheap invoice does not buy the minute. The cost is the wallet: each request past the cap still inserted a pending payment (5-second expiry on the invoice, no matching delete on the refusal). LDK keeps that row in the payment store. The session loop handles one control event at a time, so the peer can mint as fast as `create_invoice` returns for the rest of the due window, and again on the next block.

**Fix.** Amounts of 0 or above `MAX_CALL_BLOCK_INVOICE_MSAT` (1 BTC, the same ceiling as an owner invoice) are refused before the wallet. The stored binding count is read next and a full cap returns the same `konsensus:call_block_unpayable` refusal without `create_invoice`. The insert still enforces the cap in one statement, so two overlapping writers cannot both commit a ninth binding. `call_block_invoice_stops_at_the_cap_before_the_wallet` issues eight invoices, then checks that a ninth, a zero, and a 1 BTC + 1 msat request leave the wallet's payment list unchanged.

## Low — fixed

### L1 — A received file recorded the peer's size, not the bytes kept

`process_file_message` (`crates/konsensus-node/src/msg_handler.rs`). The decoded file bytes are capped and hashed before they are stored. `FileRecord.size_bytes` was copied from the peer's JSON. A matching hash with `size_bytes: u64::MAX` was stored and written to the audit line as that claim. The node does not allocate from the claim — the bytes are already in hand — but anything that trusts the stored size (the file list, a client) was reading a peer-chosen integer.

**Fix.** The stored size, the log field, and the audit field are the decoded length. `process_file_records_decoded_length_not_the_claimed_size` sends a two-byte file with `size_bytes` set to `u64::MAX` and requires the stored record to say 2.

## Low — open

### L2 — The block invoice amount is still the peer's number, under the new ceiling

After M1, a privileged peer can still request any amount from 1 msat through 1 BTC. Honest clients send the quoted kind-404 price. The gate still refuses a payment under that price, so the cheap invoice does not admit the block. Clamping the minted amount to the configured price would need the pricing engine on this path and would overlap #403. Not done. An operator price above 1 BTC is refused rather than minted.

### L3 — A provenance write that fails after `create_invoice` still leaves one wallet row

`call_block_invoice_near_deadline_is_refused_without_payment` installs an insert trigger and expects the refusal. The count is still under the cap, so the wallet is asked first and the insert then fails. One unpaid invoice remains in the backend, and the bolt11 is not returned. Closing that means reserving the binding before the wallet call, which needs a payment hash the wallet has not created yet. The unbounded repeat is M1. This single failure is left as it is.

## Info

**I1 — An unprivileged `CallMedia` is a valid frame and is then dropped.** The reader decodes it (call id of 32 hex characters, payload at most 4096 bytes) and `continue`s when the connection is not admitted (`messaging.rs`). It does not enter the media channel or the per-peer media budget. It does count toward the existing 64 MiB/minute memory budget, like any other valid frame. Disconnecting on it would change the treatment of a frame an older peer might send. Left as it is.

**I2 — Media admission is bounded per identity and per call.** `MediaIngress` allows 6400 frames/s per authenticated peer (the router's 64 calls at 100 frames/s), a burst of 64, and at most 4096 identities. The shared channel holds 512 frames and never blocks the reader. The router then admits 100 frames/s and 64 KiB/s in each direction of one call, and at most 64 attached calls. A full or idle route is dropped. Not changed.

**I3 — A call-signal plaintext is rejected before it is parsed when it exceeds `MAX_SDP_BYTES + 1024`.** Meeting rosters are then limited to 4 distinct node ids. Open calls are limited to 4 per peer and 4096 in total. Burned ids are capped and swept. Not changed.

**I4 — `paid_until_ms` on `MessageAck` cannot extend a call past a reconstructed maximum.** `receive_block_grant` ignores a grant above that maximum and ignores a grant that is not for this node's own stored, paid block. Not changed.

## Checked, not a finding

- `decode_frame` still rejects a length above `MAX_FRAME_BYTES` before the body is read. `read_noise_message` still applies `READ_TIMEOUT` to the length prefix and the body, and refuses a Noise message longer than the frame cap plus 1024 bytes.
- `Frame::CallMedia` checks the call id and the base64 token before decoding. One byte past `MAX_CALL_MEDIA_BYTES` does not become a frame.
- `stage_skipped_keys` refuses a jump of more than `MAX_SKIP` and the loop condition stops at `until`, so the counter does not wrap. A failed decrypt drops the staged keys and leaves the live session in place (`#466`).
- Session replacement (`#441`) runs X3DH only after key parsing. The negotiation cooldown map is still swept and capped. Failed offers do not erase the previous session.
- Call-block admission still goes through the payment gate's price floor. A proof under the kind-404 price is not a block.
- The starter-hub string caps and the invalid-frame leaky bucket from 2026-10-22 are unchanged.
