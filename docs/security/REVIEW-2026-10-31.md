# Security review — 2026-10-31

Signet beta. This pass covers the owner API and authentication: the local owner-control HTTP API, session and token handling, password and unlock flows including `--password-fd` and `--password-file`, pairing and device-key auth, scope checks, host and origin checks, and rate limits and lockouts on auth endpoints. The question for each path is whether a non-owner (another local process, a browser page, a LAN peer, or a tailnet peer) can reach an owner-only action.

It starts from `origin/main` at `0e10897`. The last merged report is `docs/security/REVIEW-2026-10-25.md` (payments and channel bounds, from `edb1839`). The last pass on this angle is `docs/security/REVIEW-2026-10-23.md` (from `84ca3fd`, with its own fixes through `69feeed`).

This file is a review note in the repository. It is not a public advisory. No GitHub issues were opened.

## Low — fixed in this PR

### L1 — Claim-code display did not check Host or Origin

`GET /api/v1/owner/claim-code` (`crates/konsensus-api/src/handlers/owner_claim_code.rs`, mounted in `crates/konsensus-api/src/lib.rs`). Before this PR the handler required a live `read` token, an owner actor, and a loopback `ConnectInfo`, and it refused a tunnel marker. It did not use `LocalRequestPolicy`.

`POST /api/v1/auth/local`, the locked listener, and the shared local-connection guard (WebSocket, call media, energy, membrane) already refuse a missing, duplicate, or foreign `Host`, and a foreign `Origin`. This route returns the 18-character claim code while a claim-bound enrollment is open. It was the owner-local exception.

A DNS-rebinding page still cannot mint the console token: `/auth/local` checks Host before it issues one, and the token is a bearer header, not a cookie. The gap is a browser request that already carries an owner token (the console session or an enrolled owner device) and a `Host` or `Origin` the other local routes would refuse. A non-browser local process can set `Host` itself; this check does not change that, which is the same limit as `/auth/local`.

**Fix.** The route uses `local_request::guard`, the same allowlist as `/auth/local`, built from the bound listener address. A bad header is `403` with `local_host_forbidden` or `local_origin_forbidden`, `Cache-Control: no-store`, and it does not spend the five-per-minute actor budget. Loopback, tunnel, and owner-device checks are unchanged. `foreign_host_or_origin_hides_the_code_and_does_not_spend_the_actor_budget` covers a missing host, a foreign host, a wrong port, a foreign origin, `Origin: null`, and the budget.

### L2 — `--password-file` had no size cap

`read_password_file` (`crates/konsensus-node/src/cli/seed.rs`). Before this PR it read the file with `read_to_string` after the symlink, mode, and owner checks. `--password-fd` already stops at 4096 bytes (`crates/konsensus-node/src/password.rs`) and does not put the bytes in the error.

The file must be mode `0600` or `0400` and owned by this user, so another OS user cannot point the node at a huge file. The operator, or another process running as that user, can. A multi-gigabyte file named as the password file was read into one `String` before any rejection. That can exhaust memory during startup. It does not reveal the bytes in the error, and it does not unlock the seed.

**Fix.** The read uses a fixed 4097-byte zeroizing buffer, the same ceiling as `--password-fd`, including a trailing CR/LF. Over the cap, the error names the path and the 4096-byte limit and does not include the file contents. `password_file_stops_at_4096_bytes_and_does_not_echo_the_secret` covers 4096 bytes, a 4095-byte password plus a newline, and a longer file whose marker must not appear in the error.

## Low — open

### L3 — Any paired spend token can attach to call media

`media_handler` (`crates/konsensus-api/src/call_media.rs:261`). The socket checks Host and Origin (`LocalConnection`), a live pairing, the `spend` scope, and this node's id, then `CallMediaPort::attach`, which admits the call for that peer (`crates/konsensus-node/src/call_media.rs`). It does not check that this pairing reserved the call or holds an owner device key.

A relation-intent grant puts `spend` on that client's token. The accepted note in `docs/security/device-keys.md` is that such a grant also passes spend-gated routes that move no value, with file upload as the example. Call media is new since that note. The token can send and receive the admitted call's media frames. The owner's own key-proof token and a read/receive pairing are refused. Tests lock the spend-token behavior in (`media_socket_refuses_everything_but_a_paired_spending_owner_on_an_admitted_call`).

**Fix (not applied).** Bind the socket to the pairing that holds the call reservation, or to an enrolled owner device. That changes which token the call app can use. This pass does not do it.

## Info

**I1 — A password file's mode check does not see POSIX ACLs.** `read_password_file` rejects group and world permission bits and a foreign uid. An ACL can grant another user read while the mode stays `0600`. Closing that needs an ACL read, not a mode mask. Not changed.

**I2 — Argon2id parallelism is still 1.** Unchanged from the 2026-10-23 note. Changing it would invalidate existing `.enc` files. Not changed.

## Checked, not a finding

- `/auth/local` still mints only `read` and `receive`, and only after loopback, the Host/Origin guard, and the process-wide 5/minute limiter. A rejected header does not consume that limiter.
- `/auth/token` checks the MAC before it parses the payload, requires `HS256`, rejects `crit`, and burns the challenge before the signature check. Live challenges stay capped at 128.
- Paired tokens are re-checked on every request. A scope the pairing does not currently hold is rejected. `ScopedAuth<Spend>` still refuses a paired caller on an unmetered money route. Provisional Noise sessions stay on the enrollment routes; claim-code, call media, and relation-intent are not on that list.
- `--password-fd` still reads at most 4096 bytes into a zeroizing buffer, duplicates the descriptor with `CLOEXEC`, and does not put the bytes in the error. Argv secrets still require `--insecure-argv`.
- Unlock still requires a registered tunnel peer, a device signature, then the password. Argon2 runs only after the signature check. Wrong signatures and wrong passwords share the per-key and per-window budgets. The log line is `UNLOCK_VERIFYING`.
- The LAN setup page no longer returns `sas_digest`. Approve takes the four words and compares them in constant time. CSRF, Host, and the private-LAN source check still wrap every mutation.
- Relation-intent over the tunnel still verifies the device signature against server-side node id, client id, and epoch. The remote router still omits revoke, pairing list, first-contact grant, identity replacement, `/auth/local`, metrics, and claim-code.
- Owner short codes are still compared as BLAKE3 digests. SAS confirmation still uses `subtle::ConstantTimeEq` on all 32 bytes.
