## Low — fixed in this PR

### L1 — The runtime trust bundle is one patch behind the CCADB eMudhra removal

`webpki-roots` 1.0.11 was published on 2026-10-23. The 2026-10-27 pass recorded 1.0.10 as the floor that clears `RUSTSEC-2026-0381` and did not take 1.0.11. 1.0.10 remains inside that advisory's patched range. 1.0.11 is a later bundle update: it removes emSign Root CA - C1 and emSign ECC Root CA - C3 after CCADB dropped them.

On `b3f1ad1` the 1.0.10 crate is a normal dependency of vendored `electrum-client` (spec `1.0.10`, which Cargo reads as `>=1.0.10, <2.0.0`), of `hyper-rustls` 0.27.7, and of `reqwest` 0.12.28. `cargo tree -p konsensus-node --edges normal,build` reaches it from `konsensus-lightning`, `konsensus-chain`, `konsensus-fiat`, and `konsensus-message`. The sqlx island still links `webpki-roots` 0.25.4. There is no 0.25 release after 0.25.4, and that copy stays under the existing ignore.

**Fix.** The lockfile now selects `webpki-roots` 1.0.11 (checksum `f5f280bbb2b287bc8e7de7e3852945a0ff50d1bbcb5ed42b6c7a568c546df171`, matched against the crates.io crate). No manifest edit. The 0.25.4 package entry is unchanged.

### L2 — Locked `h2` is 0.4.19

`h2` 0.4.20 (2026-10-06) is a patch on the same 0.4 line `hyper` 1.12.0 already allows. The release notes reject a GOAWAY with a non-zero stream id, a response without `:status`, and content-length values that disagree, and they count reserved push promises in the concurrency limit. RustSec has no `h2` advisory that matches 0.4.19.

`hyper`'s `h2` dependency is behind the `http2` feature. The workspace `hyper` spec enables `server` and `http1`. Workspace `reqwest` sets `default-features = false` and does not enable `http2`. Vendored `ldk-node` and `esplora-client` do the same. `cargo tree -p konsensus-node --edges normal,build` for the host target does not reach `h2`. `mockito` 1.7.2 depends on `hyper-util` with the `server-auto` feature, and `server-auto` enables `http2`. `mockito` is a dev-dependency of `konsensus-node` and `konsensus-lightning`, so those test builds compile `h2`. A release build of the node does not.

**Fix.** The lockfile now selects `h2` 0.4.20 (checksum `7d29020232d6aa3fb1daca64c1127cf662cf97f254ae16c18c05b8ab635fc118`, matched against the crates.io crate). No manifest edit. A first `cargo update -p` also rewrote several `windows-sys` edges from 0.61.2 down to 0.52.0 or 0.59.0. Those edges were put back. `cargo fetch --locked` accepts the smaller diff.
