## Medium — fixed in this PR

### M1 — Starter and Lightning-info strings were bounded only by the 16 MiB frame

`Frame::StarterRequest` and `Frame::StarterStatus` (`crates/konsensus-message/src/wire.rs`, added in `#352`) and `Frame::LightningInfo` deserialized `network`, `ln_pubkey`, `ln_sig`, `state`, `reason`, `channel_id`, `funding_txid`, and `ln_addr` as plain `String`s. `decode_frame` rejects a length above `MAX_FRAME_BYTES` before the body is read (`wire.rs` `decode_frame`). It does not stop one field inside a legal frame from being the rest of that 16 MiB.

Those variants are valid frames. The reader does not charge them to the invalid-frame budget. It awaits them onto the control channel (`crates/konsensus-message/src/transport/messaging.rs:626`, capacity 256 at `transport/mod.rs:700`). A privileged `StarterRequest` is then `try_send`ed, whole frame, onto the hub queue (`crates/konsensus-node/src/session_handler.rs:445`, capacity 64 at `crates/konsensus-node/src/main.rs:1913`). The hub builds `canonical()` with the raw `network` string and passes it to `verify_message` (`crates/konsensus-node/src/onboarding/starter_hub.rs:86` and `:164`). `LightningInfo.ln_addr` is forwarded to auto-channel and dialed after `validate_host_port` (`crates/konsensus-node/src/onboarding/auto_channel.rs:267`).

The 64 MiB memory budget disconnects the reader, but only after the bytes have been accepted. Frames already queued are retained. An oversized starter frame never became "invalid", so the budget of 10 bad frames did not apply. Any peer that finishes Noise can send these frames. Privilege is checked after decode (`session_handler.rs:216`). The hub being off does not stop decode: a privileged peer is answered `starter_disabled`, and an unprivileged `StarterRequest` is disconnected, after the strings exist.

**Exploit sketch.** A Noise peer sends `StarterRequest` frames whose `network` or `ln_sig` is several megabytes, staying under 64 MiB per minute so the memory budget does not ban them on the first frame. Each frame is valid JSON. The control channel holds the decoded `String`s. On a hub, up to 64 of them wait on `starter_hub_tx` while `handle` runs `list_channels`. The same peer can put a multi-megabyte `ln_addr` on `LightningInfo`; auto-channel will accept any `host:port` shape and hand that string to the Lightning dial.

**Fix.** The bounded string visitors already used for porch quotes and peer labels now cover these fields. Caps, in UTF-8 bytes: network 32, starter pubkey 128, signature 1024 (the hub already refused a longer signature, but only after the copy), state 32, reason 64, channel id 128, txid 128, Lightning pubkey 130, Lightning address 262 (253-byte hostname, colon, five-digit port, and headroom). One byte past the cap fails `Frame::from_bytes`, so the frame counts as invalid and the existing ban applies. Honest values still round-trip: `signet` / `regtest`, a 66-character compressed key, a 104-character LDK zbase32 signature, and a normal `host:port`. `null` reason, channel id, txid, and `ln_addr` still decode. `starter_and_lightning_info_strings_reject_one_byte_past_the_cap` and `starter_status_null_strings_and_lightning_info_without_addr_still_decode` cover it.


**PR #363 review fixes.** The shared string helper now borrows a `serde_json::value::RawValue` from the frame slice and counts decoded UTF-8 bytes before deserializing into `String`. The count handles simple escapes, Unicode escapes, and surrogate pairs without allocating. Oversized plain and escaped values are rejected before either an owned string or serde_json's unescaping scratch copy is built. Nested peer labels use this same helper. Serde still scans the whole raw token, so CPU remains bounded by the frame limit; admitted strings may use scratch space proportional to their field cap. This borrowing path is intended for `Frame::from_bytes` / serde_json `from_slice` and `from_str`, not reader-backed or prebuilt `Value` deserializers. `Frame::from_bytes` also preflights container depth (128) without allocation: RawValue otherwise uses a growing stack for nested wrong-type or ignored values. Network callers use this canonical entry point; direct serde_json calls do not get the whole-frame depth preflight. Tests cover a 1-million-level wrong-type array, the depth boundary, and escaped quotes/brackets inside strings.

The allocation regression constructs inputs before measurement and decodes 4 MiB plain, newline-escaped, Unicode-escaped, and surrogate-pair-prefixed values through required, optional, and nested-label fields. It rejects any individual decode allocation above 4 KiB (the old escaped path allocated 4,194,305–4,194,308 bytes). Escaped field names and exact decoded-byte boundaries are covered too. Other uncapped fields and JSON keys retain their existing outer-frame bounds; this is not a whole-frame allocation guarantee.

`StarterStatus.reason`, `channel_id`, and `funding_txid` retain `serde(default)`, with omitted-each and omitted-all tests in addition to explicit nulls. A real 253-byte DNS hostname with `:65535` (259 bytes total) now decodes. Config loading rejects over-cap `lightning.advertised_address` and `lightning.listening_address` (which can be advertised as the fallback), including the pre-identity bootstrap load path, with a field-specific error that states the byte limit.

The 16 MiB frame cap is unchanged. Other string fields called out on 2026-10-20 (call SDP, BOLT11, invoice reason) are not given new caps here.

## Low — open

### L1 — Starter admission does Lightning and signature work before the ten-minute throttle, and a full queue drops the request

`StarterHub::handle` (`crates/konsensus-node/src/onboarding/starter_hub.rs:160`) verifies the Lightning signature, reads the invite, and calls `list_channels` (`starter_hub.rs:219`) before the ten-minute per-requester check (`starter_hub.rs:233`). That check returns only when no earlier deny is set. A repeat from an invitee who already has a channel skips the throttle and writes another refused row. `session_handler.rs:445` uses `try_send`. When the 64-slot queue is full the frame is discarded and the peer is not told and not disconnected.

**Exploit sketch.** The hub is enabled and the attacker is a privileged invitee. They send a new `StarterRequest` as fast as the session loop will take it. Each one that the worker actually runs pays for a signature check and a channel list before the cheap throttle. Requests that arrive while the worker is inside `tick` (channel open is allowed 120 seconds) fill the queue and then vanish. Reconciliation on that same task waits behind the flood. A peer who is not invited never reaches this; unprivileged starter frames are refused first (`session_handler.rs:216`). The feature defaults off.

**Fix (not applied).** After the length and version checks, apply the ten-minute window before `list_channels`, `list_peers`, and the balance read, including when the request would be `already_served`. If `try_send` fails, disconnect that peer or enqueue a single `rate_limited` reply. Do not add a table.

## L4 follow-up: remaining peer-frame fields

Based on #363 head `42f779db`; intended as a separate follow-up after #363.
All variable-size fields reachable through `Frame` now have deserialize-time
bounds, including nested capabilities, price-map keys, prekey/session JSON,
peer-exchange quotes and UKM envelopes. Fixed-size hex types decode directly
into stack arrays rather than first allocating a `String` and decoded `Vec`.

| Fields | Maximum decoded bytes / elements |
|---|---:|
| Invoice correlation IDs and call session IDs | 256 bytes |
| MessageReject / Disconnect / InvoiceError / CallEnd reasons | 1,024 bytes |
| RequestInvoice purpose | 1,024 bytes |
| InvoiceResponse payment hash | 128 bytes |
| InvoiceResponse BOLT11 | 65,536 bytes |
| CallOffer / CallAnswer SDP | 65,536 bytes |
| ICE candidate | 4,096 bytes |
| Custom capability / price-map key | 128 bytes |
| Prekey/session JSON key / string value | 256 / 4,096 bytes |
| UKM ciphertext (Message, Gossip, paid peer-exchange request) | 6 MiB |

Admission correlation IDs contain two hex identities, a timestamp and a nonce
(up to 190 bytes), so a UUID-only limit would break first-contact payments.
The ciphertext cap retains headroom for the file API's base64/JSON encoding
and ratchet overhead. The unchanged 16 MiB outer frame limit still applies.

[BOLT11](https://github.com/lightning/bolts/blob/master/11-payment-encoding.md#tagged-fields)
permits multiple route-hint tags and has no overall character limit. The 64 KiB
invoice policy accommodates hundreds of private hops; a signed 72-hop fixture
(over 4 KiB, within the installed parser's checksum-code limit) exercises real
long-invoice compatibility. Peer-exchange quotes retain their existing 8 KiB BOLT11
cap because their bounded reply queue uses a single Noise record. Existing
starter, LightningInfo, porch, snapshot, vector-count, reference-count and JSON
node/depth bounds remain in place.

Every rejection surfaces from `Frame::from_bytes` and consumes the existing
invalid-frame budget. A transport regression sends oversized, otherwise valid
InvoiceError frames and observes a ban. The initial L4 visitors prevented oversized owned field allocations but still
allowed parser scratch for escaped strings. The round-2 follow-up below removes
that gap using the reviewed #363 raw-token helper.

The #363 P3 compatibility fixes are also included: omitted StarterStatus
`reason`, `channel_id` and `funding_txid` decode as `None`; config loading rejects
an effective advertised Lightning address above 262 bytes with a field-specific
error, including the listening-address fallback.

Regression coverage includes exact-limit/one-over values, multibyte UTF-8 and
escaped strings, omitted optional keys, nested fields, fixed-hex allocation
instrumentation, signed route-hint invoices and real encoded/encrypted file
payloads. Mutation checks disable the individual field hooks and require their
behavioral regressions to fail.

Mutation result: **40/40 detected**. The `limited_string` / `limited_opt_string`
field hooks were removed independently (including existing starter,
LightningInfo, porch and quote hooks);
separate mutants bypassed custom-capability, price-key, JSON-key/value,
ciphertext and 24/32/64-byte hex helpers. All failures were test assertions,
not build failures. The revised 256-byte ID and retained 8 KiB quote limits were
retested after the compatibility corrections.

## L4 round 2 — pre-copy strings and bounded error diagnostics

Merged `origin/cursor/peer-input-dos-review-79da` at `fcc11a51` and
`origin/main` at `3ff6ae9` with normal merge commits (`036e14f`, `69c0ef3`).
The config-test conflict retained #363's more complete address coverage. The
262-byte address cap, omitted StarterStatus optionals and 128-level frame-depth
preflight remain intact. A redundant address validation left by the automatic
merge was removed; #363's check still covers both configured addresses.

The reviewed decoded-UTF-8 byte counter now lives in
`crates/konsensus-message/src/wire/bounded_json.rs`. All L4 strings, including
price/JSON keys, nested JSON string values, custom capabilities, invoices, call
signaling and snapshots, pass through that counter on borrowed raw tokens
before decoding. Byte-array counts remain streaming bounds, with raw-token
checks also rejecting wrong-type strings at the array and byte-element levels.

Wire-only envelope adapters apply the same pre-copy check to fixed hex,
references, payment proofs, recipient Node/Room payloads and all three envelope
variants. Core identifiers and envelopes keep their generic deserialization
support: TOML privacy lists, `from_value` and `from_reader` remain compatible.
UUID and socket-address fields are bounded before parsing as well.

Unknown top-level and nested enum tags are limited to 128 decoded UTF-8 bytes
before serde unescapes or formats the unknown name. Both invalid-frame warning
paths log only a fixed error category (at most 19 ASCII bytes), with no formatting
of the underlying serde or I/O error and no raw peer bytes. The invalid-frame
budget and ban behavior are unchanged.

Allocation regressions use #363's thread-local counting allocator, now measuring
both peak request size and total allocated bytes. Inputs are built before
measurement. The matrix includes plain, escaped, multibyte and surrogate-pair
strings, every L4 string hook, nested maps/values, fixed hex, typed UUID/address
fields, unknown enum tags and wrong-type byte arrays/elements. Oversized inputs
must reject with peak allocation at most 4 KiB and total at most 16 KiB. Valid
escaped fixed-hex baselines are decoded before each hostile case so a malformed
fixture cannot mask a later-field regression. Captured tracing events exercise
both warning branches with large error strings containing secrets, newlines,
terminal escapes and non-ASCII text.

`scripts/test-peer-caps-mutations.py` preserves the 40 original L4 checks and
adds 15 checks for pre-copy ordering, nested JSON traversal, root/nested tag
checks, the exact tag boundary, both logging branches, typed identifiers and
wrong-type arrays/bytes. The four envelope/fixed-hex mutations now target the
wire adapters that own these protections; generic core serde is unchanged.
The runner requires test assertion failures rather than compilation failures,
keeps a separate log for every mutant and restores all source files afterward.


Round-2 mutation result: **55/55 detected**, all by test failures. The final
`clippy --locked -p konsensus-message -p konsensus-node --all-targets -- -D warnings`
gate passed on rustc/clippy 1.91.1. Existing dependency diagnostics remain:
`electrum-client`'s lifetime-syntax warning and the sqlx-postgres future-incompatibility
notice. No dependencies or lockfile entries were changed by this follow-up.


Scope: these bounds cover declared peer strings/bytes, their nested containers
and enum tags. They do not claim that every malformed schema type is allocation
free; for example, serde can still format a string supplied in place of a numeric
field. The fixed logging categories cover those errors too. Borrowing adapters
rely on the frame-depth preflight for untrusted frames; the existing sealed
snapshot decode is a trusted local-input path.
